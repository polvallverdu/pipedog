pipedog is an **unofficial** TypeScript port of [Pipecat](https://github.com/pipecat-ai/pipecat),
the open source Python framework (by [Daily](https://www.daily.co), BSD-2-Clause) for building
voice and multimodal AI agents. Pipecat orchestrates AI services, network transports and audio
processing for ultra-low latency conversations; pipedog brings the same architecture to
**Bun, Node, Deno and Cloudflare Workers**.

<Callout type="warn" title="Unofficial and early">
  pipedog is a community port. It is not affiliated with or endorsed by Daily or the Pipecat
  project. The core runtime is ported; most service providers and transports are not yet. See the
  [porting status](/docs/contributing/status).
</Callout>

## How it works

Like Pipecat, pipedog orchestrates work in a **pipeline**: a series of **frame processors**
that handle real-time audio, text and video **frames**. In a typical voice conversation:

1. A **transport** receives audio from the user (browser, phone, ...).
2. **Speech recognition** converts speech to text in real time.
3. An **LLM** generates a response from the conversation context.
4. **Speech synthesis** converts the response back to speech.
5. The **transport** streams the audio back to the user.

A `PipelineWorker` runs a pipeline and a `WorkerRunner` runs workers: one for a simple bot, or
many that talk to each other over a shared message bus for multi-agent setups.

## Relation to Pipecat

pipedog tracks a pinned upstream Pipecat commit and ports it module by module, test by test.
The goal is that someone who knows Pipecat can read pipedog code (and these docs) without a
dictionary:

- **Same names.** Classes, frames, module paths and file names are the same as upstream:
  `src/pipecat/processors/frame_processor.py` becomes
  `@pipedog/core/processors/frame_processor`.
- **Same event names.** `"on_pipeline_started"`, `"on_client_ready"`, ... are unchanged strings.
- **camelCase members.** `push_frame()` is `pushFrame()`, `audio_in_sample_rate` is
  `audioInSampleRate`.
- **Options objects.** Python keyword arguments become one options object:
  `new TextFrame({ text: "hi" })`.
- **Seconds.** Durations and timeouts stay in seconds, so upstream configs carry over.
- **asyncio semantics.** Tasks, cancellation, queues and events behave like Python's `asyncio`,
  through [`@pipedog/asyncio`](/docs/concepts/interruptions-and-cancellation).
- **Deprecated APIs are not ported.** Things upstream marks as deprecated (for example the
  `PipelineTask` / `PipelineRunner` aliases) are left out.

The upstream test suite is ported 1:1, and is how behavioral parity is proven.

## Compatibility with Pipecat clients (RTVI)

pipedog keeps Pipecat's **wire protocols** unchanged: RTVI messages, serializers and dict keys
on the wire are byte-for-byte what Pipecat sends. A protocol is not an API, so nothing there is
camelCased. That means Pipecat's client SDKs (`@pipecat-ai/client-js`, the React voice-ui-kit, the
prebuilt UIs) can talk to a pipedog bot unchanged. `PipelineWorker` adds RTVI support
automatically unless you pass `enableRtvi: false`.

## Status

Milestone 1, the core runtime (frames, processors, pipelines, workers, bus, observers, RTVI, base
services and transports), is ported. Service providers (STT, LLM, TTS) and most transports are
next, so a full voice bot is not possible yet. The generated
[porting status](/docs/contributing/status) (`porting/STATUS.md`) lists every package, how much of
it is ported, and which runtimes it is verified on.
