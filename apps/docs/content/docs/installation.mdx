pipedog is split into packages, like Pipecat's optional extras. They are published on npm under
the `@pipedog` scope and released together at one version: upgrade them together.

| Package | What |
|---|---|
| `@pipedog/asyncio` | asyncio semantics for JavaScript: tasks, cooperative cancellation, queues, events |
| `@pipedog/core` | frames, processors, pipelines, workers, bus, observers, RTVI, base services, transports and serializers |
| `@pipedog/tracing` | OpenTelemetry setup (`setupTracing()`, OTLP and console exporters), like `pipecat-ai[tracing]` |
| `@pipedog/audio-silero`, `@pipedog/audio-smart-turn`, `@pipedog/onnx` | Silero VAD and Smart Turn, the local turn detection models, and the ONNX backend they run on |
| `@pipedog/openai`, `@pipedog/google`, `@pipedog/anthropic`, `@pipedog/azure`, `@pipedog/aws` | LLM, speech, realtime and image services |
| `@pipedog/deepgram`, `@pipedog/cartesia`, `@pipedog/elevenlabs`, `@pipedog/inworld`, `@pipedog/whisper` | speech-to-text and text-to-speech (Inworld also realtime) |
| `@pipedog/ultravox` | Ultravox realtime speech-to-speech |
| `@pipedog/groq`, `@pipedog/mistral`, `@pipedog/together`, `@pipedog/xai` | OpenAI-compatible LLMs with the provider's STT and TTS (xAI also realtime); `@pipedog/grok` is the deprecated alias of `@pipedog/xai` |
| `@pipedog/baseten`, `@pipedog/cerebras`, `@pipedog/crusoe`, `@pipedog/deepseek`, `@pipedog/fireworks`, `@pipedog/nebius`, `@pipedog/novita`, `@pipedog/ollama`, `@pipedog/openrouter`, `@pipedog/perplexity`, `@pipedog/qwen`, `@pipedog/sambanova` | OpenAI-compatible LLMs, one package per provider |
| `@pipedog/langchain` | the LangChain processor |
| `@pipedog/flows` | [Flows](/docs/flows): structured conversations from nodes, functions and actions |
| `@pipedog/transport-websocket`, `@pipedog/transport-smallwebrtc` | transports |
| `@pipedog/serializer-protobuf`, `@pipedog/serializer-rtvi-client` | serializers for Pipecat clients |
| `@pipedog/serializer-twilio`, `@pipedog/serializer-telnyx`, `@pipedog/serializer-plivo`, `@pipedog/serializer-exotel`, `@pipedog/serializer-vonage`, `@pipedog/serializer-genesys` | telephony serializers (see [Telephony](/docs/telephony)) |
| `@pipedog/runner` | the [development runner](/docs/runner): `main()`, `createTransport()`, the prebuilt client |
| `@pipedog/evals` | [evals](/docs/evals): end-to-end tests of a bot with scripted or simulated users and an LLM judge, and the `pipedog-eval` CLI |
| `@pipedog/resampler-wasm`, `@pipedog/sentencex-wasm` | high-quality resampling and sentence segmentation, compiled to WebAssembly |
| `@pipedog/mcp` | the docs as a local MCP server for coding agents (see [Docs for AI tools](/docs/guides/llms#mcp-server)) |

Where Python installs `pipecat-ai[deepgram,openai]`, you add `@pipedog/core` plus
`@pipedog/deepgram` and `@pipedog/openai`. [Services](/docs/services) lists every provider and its
package, and [Transports](/docs/transports) the transports.

## Requirements

- **Bun**, **Node.js** 22 or later, **Deno**, or **Cloudflare Workers** (with the
  `nodejs_compat` compatibility flag, which provides `AsyncLocalStorage`).
- The npm packages ship compiled JavaScript (ES modules) with `.d.ts` types, so every runtime and
  bundler loads them as they are.
- From source, the packages are TypeScript written with erasable syntax only (no `enum`,
  `namespace` or parameter properties), so Bun and Deno run them directly and Node runs them with
  its built-in type stripping. If you type-check against the sources with `tsc`, use
  `"moduleResolution": "Bundler"` (or `"NodeNext"`) and `"allowImportingTsExtensions": true`.

## Imports

Modules are imported by their upstream path, so a Pipecat import translates directly:

```python
from pipecat.pipeline.pipeline import Pipeline
from pipecat.pipeline.worker import PipelineParams, PipelineWorker
from pipecat.workers.runner import WorkerRunner
```

```ts
import { Pipeline } from "@pipedog/core/pipeline/pipeline";
import { PipelineParams, PipelineWorker } from "@pipedog/core/pipeline/worker";
import { WorkerRunner } from "@pipedog/core/workers/runner";
```

## From source

To work on pipedog itself, or to run unreleased changes: pipedog is a Bun monorepo. Clone it,
install, and add your app as a workspace (for example under `examples/`), depending on the packages
with `workspace:*`:

```bash
bun install
bun test            # the ported upstream test suite
bun run typecheck   # tsc over every package
```

```json title="examples/my-bot/package.json"
{
  "name": "my-bot",
  "private": true,
  "type": "module",
  "dependencies": {
    "@pipedog/asyncio": "workspace:*",
    "@pipedog/core": "workspace:*"
  }
}
```

Then continue with the [Quickstart](/docs/quickstart).
