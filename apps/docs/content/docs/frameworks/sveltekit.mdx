title: SvelteKit
description: Mount the pipedog WebRTC offer endpoint in a SvelteKit +server.ts route.
---

A `+server.ts` route handles `POST /api/offer`. SvelteKit hands the route a web `Request`, so the
route passes it to `offer` unchanged.

## Install

```bash
bun add @pipedog/core @pipedog/asyncio @pipedog/transport-smallwebrtc @pipedog/transport-websocket @pipedog/serializer-protobuf @pipedog/openai @pipedog/audio-silero @pipedog/audio-smart-turn @sveltejs/kit
```

`@pipedog/audio-smart-turn` isn't imported anywhere: the default turn strategies load it. To run
the snippet from a checkout instead, see [Installation](/docs/installation#from-source).

## Files

`$lib/voice` re-exports it:

## Run it

```bash
OPENAI_API_KEY=sk-... bunx vite dev
```

The browser then POSTs its SDP offer to `/api/offer`.

## Deploy

Use an adapter that runs a Node, Bun or Deno server, such as `@sveltejs/adapter-node`
(`bun add -d @sveltejs/adapter-node`, then set it in `svelte.config.js`). The serverless adapters (Vercel, Netlify, Cloudflare) don't carry the UDP media.

## WebSocket

This snippet mounts only the offer. To serve `socket` too, run it on a server that upgrades
WebSockets next to the SvelteKit app: [Bun](/docs/frameworks/bun), [Deno](/docs/frameworks/deno),
or `serveFetch(socket, { port })` from `@pipedog/transport-websocket/serve` on Node, Bun or Deno.

## Authentication

The route has no auth. Wrap `offer` with a session check before it runs, as in
[Authentication](/docs/frameworks#authentication).
