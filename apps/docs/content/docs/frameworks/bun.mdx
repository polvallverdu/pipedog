---
title: Bun
description: Serve the pipedog WebRTC offer and WebSocket endpoints with Bun.serve.
---

`Bun.serve` routes both endpoints. `socket` is a fetch handler that upgrades `/ws` with the server
Bun passes to `fetch`, and the `bunWebSocket` handlers deliver each socket's messages and close to
the agent's `WebsocketConnection`.

## Install

```bash
bun add @pipedog/core @pipedog/asyncio @pipedog/transport-smallwebrtc @pipedog/transport-websocket @pipedog/serializer-protobuf @pipedog/openai @pipedog/audio-silero @pipedog/audio-smart-turn
```

`@pipedog/audio-smart-turn` isn't imported anywhere: the default turn strategies load it. To run
the snippet from a checkout instead, see [Installation](/docs/installation#from-source).

Bun upgrades on its server, not from the `Request` alone, so pass `server` on to `socket` (or to
`upgradeWebSocket(request, { server })` from `@pipedog/transport-websocket/fetch`) and serve with
`websocket: bunWebSocket`. To serve any fetch handler with WebSocket upgrades on Bun, Node or Deno
without this wiring, use `serveFetch()` from `@pipedog/transport-websocket/serve`; see
[WebSocket](/docs/transports/websocket).

## Run it

```bash
OPENAI_API_KEY=sk-... bun server.ts
```

Bun serves the default export on port 3000, or on `$PORT`. The offer is at `POST /api/offer` and the
WebSocket at `/ws`.

## Deploy

Run it as a long-lived Bun process on a host that allows UDP traffic, for the offer's media. To serve
the same config on Vercel Functions, see [Vercel](/docs/frameworks/vercel).

## Authentication

Neither route has auth. Check the session in `fetch` before `offer` and `socket` run, as in [Authentication](/docs/frameworks#authentication).
