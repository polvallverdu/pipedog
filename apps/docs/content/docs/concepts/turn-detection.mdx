---
title: Turn detection
description: Decide when the user has finished speaking, with local models, with VAD only, or on the provider's side.
---

A voice agent has to know when the user starts speaking, to stop talking, and when they've
finished, to answer. pipedog does this in one of three ways. They differ in what runs on your
server: two local models, one, or none.

| Mode | Start of turn | End of turn | Runs locally |
| --- | --- | --- | --- |
| Local models (default) | Silero VAD | Smart Turn | ONNX runtime, two models |
| VAD only | Silero VAD | silence | ONNX runtime, one model |
| Provider | the STT service | the STT service | nothing |

Each mode is a choice of [turn strategies](/docs/concepts/turn-strategies) on the user aggregator.
This page covers the three common setups; the strategies page covers every strategy and option.

## Local models

Silero VAD hears speech; Smart Turn listens to the end of each utterance and decides whether the user
is done or only paused. This is Pipecat's default, and pipedog's:

<include cwd>snippets/turn_strategies.ts#local-models</include>

The default turn strategies use Smart Turn from `@pipedog/audio-smart-turn`, so install it next to
`@pipedog/audio-silero`. Without it, turns end on silence (the VAD-only mode), and pipedog logs a
warning once.

Both models share one inference session per process: the first call loads them, and later calls
reuse them. Measured on Bun with `onnxruntime-node`, the first call takes about 100 MB for the runtime
and both models, and each further call about 1.3 MB.

## VAD only

Leave out `@pipedog/audio-smart-turn`, or end turns on silence explicitly:

<include cwd>snippets/turn_strategies.ts#vad-only</include>

This answers sooner after a pause than Smart Turn does, so it interrupts users who pause to think more
often.

## Remote Smart Turn over HTTP

If you can't run the model on the bot's host (a Worker, a small container), run Smart Turn as a
service and let the bot send it the audio. `HttpSmartTurnAnalyzer` posts each candidate turn to an
endpoint and reads the verdict back. It needs only `fetch`, so it works on every runtime, Cloudflare
Workers included.

<RuntimeMatrix pkg="@pipedog/audio-smart-turn" />

<include cwd>snippets/turn_strategies.ts#http-smart-turn</include>

It goes where the local analyzer does, in a `TurnAnalyzerUserTurnStopStrategy` (see
[turn strategies](/docs/concepts/turn-strategies)); `params: new SmartTurnParams({ stopSecs, ... })` takes the same settings. It makes the same request as Pipecat's: a `POST` of
the audio (up to `maxDurationSecs`, as a NumPy `.npy` float32 vector at the analyzer's sample rate) with
`Content-Type: application/octet-stream`, and expects JSON with a `prediction` (1 when the user is
done) and a `probability`. Any failure, a non-200 status, a timeout after `stopSecs` or a body that
isn't JSON, is logged and counts as "not done", as upstream does. `fetch` replaces the `aiohttp`
session; pass your own as the `fetch` option.

Pipecat's older `LocalSmartTurnAnalyzerV2` and the Core ML variant need PyTorch or Core ML and are
not ported: Smart Turn v3, the default above, replaces them.

## Provider

Some speech-to-text services detect turns themselves. Use one of them and pass no VAD analyzer: the
user aggregator follows the service's turn signals, and nothing runs locally.

<include cwd>snippets/turn_strategies.ts#provider</include>

This is the mode for constrained hosts. The
[Durable Objects example](/docs/deployment/cloudflare-workers) uses it: its Worker is 818 KB gzipped, against 13.7 MB with
the local models, which is over Cloudflare's 10 MB limit for a Worker.

Speech-to-text services with their own turn detection:

- `OpenAIRealtimeSTTService` (`@pipedog/openai/stt`) with `turnDetection: { type: "server_vad" }`.
- `DeepgramFluxSTTService` (`@pipedog/deepgram/flux/stt`): Deepgram's turn-taking model.
- `CartesiaTurnsSTTService` (`@pipedog/cartesia/turns/stt`).

Each of these recommends its own turn strategies to the user aggregator
([`ExternalUserTurnStrategies`](/docs/concepts/turn-strategies#externaluserturnstrategies)), so
passing no VAD analyzer is all it takes. To keep the bot talking when the provider hears the user,
pass `shouldInterrupt: false` to the service rather than configuring the strategies yourself.
