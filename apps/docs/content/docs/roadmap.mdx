pipedog ports Pipecat module by module, against a pinned upstream commit, and ports each module's
tests with it. The generated status file,
[`porting/STATUS.md`](https://github.com/polvallverdu/pipedog/blob/main/porting/STATUS.md), is the
source of truth: it lists every package, the share of its upstream modules and tests that are
ported, and the runtimes it is verified on. The [porting status](/docs/contributing/status) page
renders the same file.

## At a glance

Against the pinned upstream commit (counts from `porting/manifest.json`):

| | Ported | Upstream | Share |
|---|---|---|---|
| Modules | 502 | 667 | 75% (64% of the lines) |
| Test files | 244 | 340 | 72% |
| Core modules (`@pipedog/core`) | 361 | 361 | 100% |
| Core test files | 150 | 150 | 100% |
| Target packages | 43 started, 62 not | 105 | |

pipedog publishes 49 packages: those 43, plus six with no upstream counterpart (`@pipedog/asyncio`,
`@pipedog/mcp`, `@pipedog/onnx`, `@pipedog/resampler-wasm`, `@pipedog/sentencex-wasm`,
`@pipedog/tracing`).

<Callout title="How it is tested">
  Ported code runs against its ported upstream tests, mock provider servers and recorded protocol
  vectors, and the examples run end to end against mock APIs (in headless Chromium, on Deno and on
  workerd). Tests that need real API keys are skipped by default, as upstream does. Testing
  against the real providers is the next phase; until then, expect provider-specific bugs that
  mocks can't catch, and please report them.
</Callout>

## Ported

- **Core runtime**: frames, processors, pipelines, workers and the runner, the bus, observers,
  RTVI, base services and transports, turn management. See [Core concepts](/docs/concepts/frames).
- **Local audio models**: Silero VAD and Smart Turn. See
  [Turn detection](/docs/concepts/turn-detection).
- **Services**: OpenAI, Google, Anthropic, Deepgram, Cartesia, ElevenLabs, the Whisper base and
  LangChain. See [Supported services](/docs/services).
- **Cloud platforms**: Azure (Azure OpenAI LLM, Realtime and image, Voice Live, Azure Speech STT
  and TTS) and AWS (Bedrock LLM, Transcribe STT, Polly TTS, Nova Sonic, AgentCore and the
  SageMaker streaming client).
- **Realtime speech-to-speech**: OpenAI Realtime, Gemini Live, Azure Voice Live, AWS Nova Sonic,
  xAI Grok Voice Agent, Inworld Realtime and Ultravox.
- **OpenAI-compatible providers**: Baseten, Cerebras, Crusoe, DeepSeek, Fireworks AI, Groq,
  Mistral, Nebius, Novita AI, Ollama, OpenRouter, Perplexity, Qwen, SambaNova, Together AI and xAI
  (plus `@pipedog/grok`, the deprecated alias), one small package each. Groq, Mistral, Together AI
  and xAI come with their speech-to-text and text-to-speech services.
- **Speech providers**: Inworld TTS, alongside the Deepgram, Cartesia, ElevenLabs, Google, Azure
  and AWS speech services above.
- **Transports**: [WebSocket](/docs/transports/websocket) (server, client, fetch handlers, and
  `serveFetch` for WebSocket upgrades on Bun, Node and Deno) and
  [SmallWebRTC](/docs/transports/smallwebrtc).
- **Serializers**: [Protobuf](/docs/serializers/protobuf),
  [RTVI client](/docs/serializers/rtvi-client), and the telephony serializers for
  [Twilio](/docs/serializers/twilio), [Telnyx](/docs/serializers/telnyx),
  [Plivo](/docs/serializers/plivo), [Exotel](/docs/serializers/exotel),
  [Vonage](/docs/serializers/vonage) and [Genesys](/docs/serializers/genesys). See
  [Telephony](/docs/telephony).
- **Runner**: the [development runner](/docs/runner) (`main()`, the prebuilt client,
  WebRTC and telephony routes, `serve()` and `createRunnerApp()`) and `createTransport`, in
  `@pipedog/runner`.
- **Tracing**: OpenTelemetry, in `@pipedog/tracing`. See
  [Metrics & tracing](/docs/concepts/metrics-and-tracing).

## What's not ported yet

165 upstream modules (36% of the lines) and 96 test files are still to do. Every upstream provider
that isn't ported has a "coming soon" page, or a row on
[Other upstream providers](/docs/services/other-upstream). The main gaps, with their remaining
upstream modules:

| Gap | Modules | What it is |
|---|---|---|
| Transports | 16 | [Daily](/docs/transports/daily) (with its runner routes and dial-in), [LiveKit](/docs/transports/livekit), [local audio](/docs/transports/local-audio), the [Vonage Video Connector](/docs/transports/vonage), [WhatsApp](/docs/transports/whatsapp), and the HeyGen, Tavus, LemonSlice and MoQ transports. |
| Evals | 31 | `pipecat.evals`, Pipecat's harness for evaluating bots (`@pipedog/evals`). |
| CLI | 17 | The `pipecat` command line tool (`@pipedog/cli`). |
| Pipecat Flows | 8 | Structured conversation flows (`@pipedog/flows`). |
| Audio filters and analyzers | 12 | Noise filters (Krisp VIVA, RNNoise, Koala, AIC), Krisp and AIC VAD and turn models, the soundfile mixer, and Smart Turn v2, CoreML and HTTP (Smart Turn v3, the default, is ported). |
| Extensions | 5 | The IVR navigator and voicemail detector in `pipecat.extensions` (`@pipedog/extensions`). |
| MCP client service | 1 | `pipecat.services.mcp_service`, which gives an LLM the tools of an MCP server (`@pipedog/mcp-client`). Not to be confused with [`@pipedog/mcp`](/docs/guides/llms#mcp-server), the docs server, which exists. |
| Providers with a page | 30 | 12 providers: AssemblyAI, Gladia, NVIDIA (LLM, Riva STT and TTS), Sarvam AI, Soniox, Speechmatics, Fish Audio, Hume, Rime, and the HeyGen, Simli and Tavus video avatars. |
| Long-tail providers | 24 | 22 smaller providers, from Async to XTTS, listed on [Other upstream providers](/docs/services/other-upstream). |
| Variants of ported providers | 10 | Deepgram and NVIDIA on SageMaker, ElevenLabs Dialogue, local Whisper. |
| Message buses | 3 | The Redis and pgmq buses (`@pipedog/bus-redis`, `@pipedog/bus-pgmq`). |
| Other | 8 | Sentry metrics, the OpenClaw gateway, Strands Agents, the WebSocket worker proxy, GStreamer. |

There are no dates. Ports happen in the order people need them.

## Ask for a port

1. Look for the provider on its coming-soon page, which links to a search of the issues.
2. Upvote an existing request with a reaction, or open one with the
   [port request template](https://github.com/polvallverdu/pipedog/issues/new?template=feature_request.yml).
3. Or port it yourself: [Contributing](/docs/contributing) explains the workflow, from
   `bun tools/port/next.ts` to the ported tests.
