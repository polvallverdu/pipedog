pipedog ports Pipecat module by module, against a pinned upstream commit, and ports each module's
tests with it. The generated status file,
[`porting/STATUS.md`](https://github.com/polvallverdu/pipedog/blob/main/porting/STATUS.md), is the
source of truth: it lists every package, the share of its upstream modules and tests that are
ported, and the runtimes it is verified on. The [porting status](/docs/contributing/status) page
renders the same file.

## At a glance

Against the pinned upstream commit (counts from `porting/manifest.json`):

| | Ported | Upstream | Share |
|---|---|---|---|
| Modules | 576 | 667 | 86% (79% of the lines) |
| Test files | 273 | 340 | 80% |
| Core modules (`@pipedog/core`) | 361 | 361 | 100% |
| Core test files | 150 | 150 | 100% |
| Target packages | 54 started, 51 not | 105 | |

pipedog publishes 60 packages: all 54 of those, plus six with no upstream counterpart
(`@pipedog/asyncio`, `@pipedog/mcp`, `@pipedog/onnx`, `@pipedog/resampler-wasm`,
`@pipedog/sentencex-wasm`, `@pipedog/tracing`).

<Callout title="How it is tested">
  Ported code runs against its ported upstream tests, mock provider servers and recorded protocol
  vectors, and the examples run end to end against mock APIs (in headless Chromium, on Deno and on
  workerd). Tests that need real API keys are skipped by default, as upstream does. Testing
  against the real providers is the next phase; until then, expect provider-specific bugs that
  mocks can't catch, and please report them.
</Callout>

## Ported

- **Core runtime**: frames, processors, pipelines, workers and the runner, the bus, observers,
  RTVI, base services and transports, turn management. See [Core concepts](/docs/concepts/frames).
- **Local audio models and filters**: Silero VAD and Smart Turn (local v3, and
  `HttpSmartTurnAnalyzer` for a remote endpoint), the RNNoise noise filter and the soundfile mixer.
  See [Turn detection](/docs/concepts/turn-detection).
- **Services**: OpenAI, Google, Anthropic, Deepgram, Cartesia, ElevenLabs, the Whisper base and
  LangChain. See [Supported services](/docs/services).
- **Cloud platforms**: Azure (Azure OpenAI LLM, Realtime and image, Voice Live, Azure Speech STT
  and TTS) and AWS (Bedrock LLM, Transcribe STT, Polly TTS, Nova Sonic, AgentCore and the
  SageMaker streaming client).
- **Realtime speech-to-speech**: OpenAI Realtime, Gemini Live, Azure Voice Live, AWS Nova Sonic,
  xAI Grok Voice Agent, Inworld Realtime and Ultravox.
- **OpenAI-compatible providers**: Baseten, Cerebras, Crusoe, DeepSeek, Fireworks AI, Groq,
  Mistral, Nebius, Novita AI, Ollama, OpenRouter, Perplexity, Qwen, SambaNova, Together AI and xAI
  (plus `@pipedog/grok`, the deprecated alias), one small package each. Groq, Mistral, Together AI
  and xAI come with their speech-to-text and text-to-speech services.
- **Speech providers**: Inworld TTS, alongside the Deepgram, Cartesia, ElevenLabs, Google, Azure
  and AWS speech services above.
- **Transports**: [WebSocket](/docs/transports/websocket) (server, client, fetch handlers, and
  `serveFetch` for WebSocket upgrades on Bun, Node and Deno),
  [SmallWebRTC](/docs/transports/smallwebrtc), [LiveKit](/docs/transports/livekit),
  [WhatsApp](/docs/transports/whatsapp) calling and [local audio](/docs/transports/local-audio)
  (microphone and speakers).
- **Video avatars**: [HeyGen](/docs/services/video/heygen) (LiveAvatar and Interactive Avatar),
  as a service and as a transport.
- **Serializers**: [Protobuf](/docs/serializers/protobuf),
  [RTVI client](/docs/serializers/rtvi-client), and the telephony serializers for
  [Twilio](/docs/serializers/twilio), [Telnyx](/docs/serializers/telnyx),
  [Plivo](/docs/serializers/plivo), [Exotel](/docs/serializers/exotel),
  [Vonage](/docs/serializers/vonage) and [Genesys](/docs/serializers/genesys). See
  [Telephony](/docs/telephony).
- **Runner**: the [development runner](/docs/runner) (`main()`, the prebuilt client,
  WebRTC and telephony routes, `serve()` and `createRunnerApp()`) and `createTransport`, in
  `@pipedog/runner`.
- **Evals**: [Pipecat's evals](/docs/evals) in `@pipedog/evals`: scripted and simulated
  scenarios, the LLM judge, suites, and the `pipedog-eval` CLI (`pipecat eval`).
- **CLI**: the [`pipedog` command](/docs/cli) in `@pipedog/cli`: `pipedog init` (project
  scaffolding for a registry of the ported services, the config validator, coding-agent guides and
  the docs MCP server) and `pipedog eval`. The Context Hub's freshness check is skipped.
- **Flows**: [Pipecat Flows](/docs/flows) in `@pipedog/flows`: nodes, functions, actions, and
  YAML/JSON configs.
- **Tracing**: OpenTelemetry, in `@pipedog/tracing`. See
  [Metrics & tracing](/docs/concepts/metrics-and-tracing).

## What's not ported yet

91 upstream modules (21% of the lines) and 67 test files are still to do. Every upstream provider
that isn't ported has a "coming soon" page, or a row on
[Other upstream providers](/docs/services/other-upstream). The main gaps, with their remaining
upstream modules:

| Gap | Modules | What it is |
|---|---|---|
| Transports | 9 | [Daily](/docs/transports/daily) (with its runner routes and dial-in), the [Vonage Video Connector](/docs/transports/vonage), and the Tavus, LemonSlice and MoQ transports. |
| Audio filters and analyzers | 7 | Noise filters (Krisp VIVA, Koala, AIC), and the Krisp and AIC VAD and turn models. Smart Turn v3, RNNoise, the soundfile mixer and HTTP Smart Turn are ported. |
| Extensions | 5 | The IVR navigator and voicemail detector in `pipecat.extensions` (`@pipedog/extensions`). |
| Providers with a page | 25 | 11 providers: AssemblyAI, Gladia, NVIDIA (LLM, Riva STT and TTS), Sarvam AI, Soniox, Speechmatics, Fish Audio, Hume, Rime, and the Simli and Tavus video avatars. |
| Long-tail providers | 24 | 22 smaller providers, from Async to XTTS, listed on [Other upstream providers](/docs/services/other-upstream). |
| Variants of ported providers | 10 | Deepgram and NVIDIA on SageMaker, ElevenLabs Dialogue, local Whisper. |
| Message buses | 3 | The Redis and pgmq buses (`@pipedog/bus-redis`, `@pipedog/bus-pgmq`). |
| Other | 8 | Sentry metrics, the OpenClaw gateway, Strands Agents, the WebSocket worker proxy, GStreamer. |

There are no dates. Ports happen in the order people need them.

## Blocked or deferred

Some upstream pieces can't be ported today, or aren't worth porting yet. Each has a reason, and
a condition that would change that. "Blocked" means there is no viable JS path today. "Deferred"
means it is possible, but needs vendor SDKs or keys, or waits on a moving spec. Last assessed on
2026-10-21.

| Item | Status | Why | What would unblock it | Source |
|---|---|---|---|---|
| [Daily](/docs/transports/daily) transport, plus [Tavus](/docs/services/video/tavus) and [LemonSlice](/docs/transports/lemonslice), which run on Daily rooms | Blocked | Upstream uses the native `daily-python` SDK. Daily publishes no headless or server-side JS SDK, and `@daily-co/daily-js` is browser-only. | Daily ships a Node or server SDK, or someone builds a headless media path. The REST helpers for rooms and tokens are portable now, and a pull request would be accepted. | [daily-js quickstart](https://docs.daily.co/docs/daily-js/quickstart), [LemonSlice](https://docs.pipecat.ai/server/services/transport/lemonslice), [Tavus](https://docs.pipecat.ai/api-reference/server/services/transport/tavus) |
| [Vonage Video Connector](/docs/transports/vonage) | Blocked | Upstream uses a native, Python-only SDK. Vonage lists "Node.js coming soon". The Vonage voice (Audio Connector) [serializer](/docs/serializers/vonage) is already ported. | Vonage ships its Node SDK. | [Vonage AI connectors](https://developer.vonage.com/en/video/ai-connectors/overview) |
| [MoQ](/docs/transports/moq) transport | Deferred | The protocol is still changing. The JS library, `@moq/net`, falls back to WebSocket on servers and only has experimental WebTransport. | The spec and server-side JS support settle. | [MoQ JS docs](https://doc.moq.dev/js/) |
| Krisp VIVA (filter, VAD, turn) | Deferred | The proprietary SDK isn't on public npm, and it needs a Krisp license and models. The hook `setKrispAudioSdk()` (in `@pipedog/core`) is ported, so you can plug in your own copy of the SDK. | A bring-your-own-SDK package is planned. | Krisp's SDK terms |
| ai-coustics (AIC) filter and Quail VAD | Deferred | `@ai-coustics/aic-sdk` is native (darwin and linux), and the other build is WASM, aimed at browsers. Both need a license key. | Planned as an optional package. | `@ai-coustics/aic-sdk` on npm |
| Koala (Picovoice) noise suppression | Deferred | There is no Node build, only `@picovoice/koala-web` (WASM, for browsers), and it needs an AccessKey. | It will be ported if users ask: [open a request](https://github.com/polvallverdu/pipedog/issues/new?template=feature_request.yml). | `@picovoice/koala-web` on npm |
| Tk local transport, Smart Turn v2 and Smart Turn CoreML | Skipped | Skipped on purpose. Tk is a desktop GUI, and both Smart Turn variants are superseded by v3, which is ported. | Nothing planned. Open a request if you have a use for one. | |

Contributions are welcome on any of these, especially the portable parts (the REST helpers for
Daily, Tavus and LemonSlice) and the bring-your-own-SDK packages. Open a request with the
[port request template](https://github.com/polvallverdu/pipedog/issues/new?template=feature_request.yml)
first, so the work isn't duplicated.

## Ask for a port

1. Look for the provider on its coming-soon page, which links to a search of the issues.
2. Upvote an existing request with a reaction, or open one with the
   [port request template](https://github.com/polvallverdu/pipedog/issues/new?template=feature_request.yml).
3. Or port it yourself: [Contributing](/docs/contributing) explains the workflow, from
   `bun tools/port/next.ts` to the ported tests.
