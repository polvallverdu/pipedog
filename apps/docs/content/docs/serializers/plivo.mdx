## Overview

**`PlivoFrameSerializer`** speaks Plivo's audio streaming WebSocket protocol. Paired with
[`FastAPIWebsocketTransport`](/docs/transports/websocket), it lets a bot answer phone calls:

- Caller audio (`media` events, μ-law at 8 kHz) becomes `InputAudioRawFrame`s at the pipeline's
  input rate.
- Bot audio is resampled to 8 kHz, μ-law encoded and sent as `playAudio` events.
- Touch-tone digits become `InputDTMFFrame`s.
- An `InterruptionFrame` sends `clearAudio`.
- An `EndFrame` or `CancelFrame` hangs up the call through Plivo's REST API (`autoHangUp`).

See [How phone calls connect](/docs/telephony) for the overall flow.

## Installation

```bash
bun add @pipedog/serializer-plivo @pipedog/transport-websocket @pipedog/runner
```

```ts
import { PlivoFrameSerializer } from "@pipedog/serializer-plivo/plivo";
```

## Prerequisites

- A Plivo account and a number whose answer XML has a bidirectional
  `<Stream bidirectional="true" keepCallAlive="true">wss://your.host/ws</Stream>`.
- Your auth ID and auth token, for auto hang-up. The examples read them from `PLIVO_AUTH_ID` and
  `PLIVO_AUTH_TOKEN`.
- The stream ID and call ID, which Plivo sends in its `start` message.

### InputParams

`params` is a `PlivoFrameSerializer.InputParams` (`PlivoFrameSerializerInputParams`):

| Param | Type | Default | Description |
|---|---|---|---|
| `plivoSampleRate` | `number` | `8000` | Sample rate Plivo uses, in Hz. |
| `sampleRate` | `number \| null` | `null` | Override for the pipeline input rate. `null` uses the pipeline's. |
| `autoHangUp` | `boolean` | `true` | Hang up the call on `EndFrame` or `CancelFrame`. |
| `resamplerClearAfterSecs` | `number \| null` | `0.2` | Seconds of silence after which the stream resamplers clear their history. `null` never clears. |
| `ignoreRtviMessages` | `boolean` | `true` | Drop RTVI messages instead of sending them to Plivo. |

### Notes

- With `autoHangUp` on (the default), the constructor throws if `callId`, `authId` or `authToken`
  is missing. The hang-up is a `DELETE` of
  `https://api.plivo.com/v1/Account/{authId}/Call/{callId}/` with Basic auth, attempted once. 204
  and 404 (already ended) are logged at debug level; other failures are logged as errors and don't
  throw.
- Outbound audio is `playAudio` with `contentType: "audio/x-mulaw"` and the Plivo sample rate.
- Set `addWavHeader: false` on the transport params.
- An invalid DTMF digit is logged as a warning and ignored.

## Runtime notes

Runs on Bun, Node, Deno and Cloudflare Workers (`fetch` for the hang-up, core's WASM resampler for
the audio). The package's golden tests replay vectors recorded from upstream: at 8 kHz the wire
output is byte-identical.
