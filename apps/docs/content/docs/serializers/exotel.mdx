## Overview

**`ExotelFrameSerializer`** speaks the WebSocket protocol of Exotel's Stream and Voicebot applets.
Paired with [`FastAPIWebsocketTransport`](/docs/transports/websocket), it lets a bot answer phone
calls:

- Caller audio (16-bit PCM at 8 kHz, base64 in `media` events) becomes `InputAudioRawFrame`s at
  the pipeline's input rate.
- Bot audio is resampled to 8 kHz and sent as `media` events.
- Touch-tone digits become `InputDTMFFrame`s.
- An `InterruptionFrame` sends `clear`.

There is no hang-up REST call: the call ends when the stream closes. See
[How phone calls connect](/docs/telephony) for the overall flow.

## Installation

```bash
bun add @pipedog/serializer-exotel @pipedog/transport-websocket @pipedog/runner
```

```ts
import { ExotelFrameSerializer } from "@pipedog/serializer-exotel/exotel";
```

## Prerequisites

- An Exotel account with a call flow whose Voicebot applet points at your WebSocket URL.
- The stream SID (and call SID), which Exotel sends in its `start` message.

## ExotelFrameSerializer

### Configuration

<auto-type-table cwd path="../../packages/serializer-exotel/src/exotel.ts" name="ExotelFrameSerializerOptions" />

### InputParams

`params` is an `ExotelFrameSerializer.InputParams` (`ExotelFrameSerializerInputParams`):

| Param | Type | Default | Description |
|---|---|---|---|
| `exotelSampleRate` | `number` | `8000` | Sample rate Exotel uses, in Hz. |
| `sampleRate` | `number \| null` | `null` | Override for the pipeline input rate. `null` uses the pipeline's. |
| `resamplerClearAfterSecs` | `number \| null` | `0.2` | Seconds of silence after which the stream resamplers clear their history. `null` never clears. |
| `ignoreRtviMessages` | `boolean` | `true` | Drop RTVI messages instead of sending them to Exotel. |

### Notes

- `callSid` is stored but not used: Exotel has no hang-up call here.
- The audio is linear PCM, not μ-law: only resampled, never companded.
- An invalid DTMF digit is logged at info level and ignored.
