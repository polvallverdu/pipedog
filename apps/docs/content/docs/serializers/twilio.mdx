## Overview

**`TwilioFrameSerializer`** speaks Twilio's Media Streams WebSocket protocol. Paired with
[`FastAPIWebsocketTransport`](/docs/transports/websocket), it lets a bot answer phone calls:

- Caller audio (μ-law at 8 kHz) becomes `InputAudioRawFrame`s at the pipeline's input rate.
- Bot audio is resampled to 8 kHz, μ-law encoded and sent as `media` events.
- Touch-tone digits become `InputDTMFFrame`s.
- An `InterruptionFrame` sends `clear`, so Twilio drops the audio it has buffered.
- An `EndFrame` or `CancelFrame` hangs up the call through Twilio's REST API (`autoHangUp`).

New to phone bots? Start with [How phone calls connect](/docs/telephony) and the
[Twilio quickstart](/docs/telephony/twilio-quickstart).

## Installation

```bash
bun add @pipedog/serializer-twilio @pipedog/transport-websocket @pipedog/runner
```

```ts
import { TwilioFrameSerializer } from "@pipedog/serializer-twilio/twilio";
```

## Prerequisites

- A Twilio account and a phone number with voice, whose incoming-call webhook returns TwiML with
  `<Connect><Stream url="wss://your.host/ws" />`.
- Your account SID and auth token, for auto hang-up. The examples read them from
  `TWILIO_ACCOUNT_SID` and `TWILIO_AUTH_TOKEN`.
- The stream SID and call SID, which Twilio sends in its `start` message.
  [`parseTelephonyWebsocket`](/docs/telephony#reading-the-handshake) reads them for you.

## TwilioFrameSerializer

### Configuration

<auto-type-table cwd path="../../packages/serializer-twilio/src/twilio.ts" name="TwilioFrameSerializerOptions" />

### InputParams

`params` is a `TwilioFrameSerializer.InputParams` (`TwilioFrameSerializerInputParams`):

| Param | Type | Default | Description |
|---|---|---|---|
| `twilioSampleRate` | `number` | `8000` | Sample rate Twilio uses, in Hz. |
| `sampleRate` | `number \| null` | `null` | Override for the pipeline input rate. `null` uses the pipeline's. |
| `autoHangUp` | `boolean` | `true` | Hang up the call on `EndFrame` or `CancelFrame`. |
| `resamplerClearAfterSecs` | `number \| null` | `0.2` | Seconds of silence after which the stream resamplers clear their history. `null` never clears. |
| `ignoreRtviMessages` | `boolean` | `true` | Drop RTVI messages instead of sending them to Twilio. |

### Notes

- With `autoHangUp` on (the default), the constructor throws if `callSid`, `accountSid` or
  `authToken` is missing, or if only one of `region` and `edge` is set (unless `baseUrl` is).
- The hang-up is a `POST` of `Status=completed` to
  `https://api.twilio.com/2010-04-01/Accounts/{accountSid}/Calls/{callSid}.json` with Basic auth,
  attempted once. A 404 with code 20404 (call already ended) is logged at debug level; other
  failures are logged as errors and don't throw. `baseUrl` replaces the host, for a
  Twilio-compatible API.
- When the caller hangs up first, the socket is already closed, so no hang-up request is made.
- Set `addWavHeader: false` on the transport params: Twilio takes raw μ-law.
- `OutputTransportMessageFrame`s are sent as JSON, except RTVI messages while
  `ignoreRtviMessages` is on.
- A DTMF event whose digit is not a keypad key is ignored. Malformed JSON and `media` events
  without a payload are ignored too.

## Runtime notes

<RuntimeMatrix pkg="@pipedog/serializer-twilio" />

The serializer uses the global `fetch` for the hang-up and runs on Bun, Node, Deno and Cloudflare
Workers. Accept the Twilio WebSocket with `websocketFetchHandler` (Deno, Workers) or any of the
[WebSocket](/docs/transports/websocket) server adapters.

Resampling between 8 kHz and the pipeline rate goes through core's resampler engine
(`@pipedog/resampler-wasm` by default) in place of libsoxr, so resampled samples differ slightly
from upstream's. At 8 kHz the wire output is byte-identical; the package's golden tests replay
vectors recorded from upstream.
