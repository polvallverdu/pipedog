## Overview

Nebius Token Factory serves open models through an OpenAI-compatible API.

- **`NebiusLLMService`**: an `OpenAILLMService` subclass with Nebius's base URL and default
  model.

## Installation

```bash
bun add @pipedog/nebius
```

It depends on `@pipedog/openai`, which is installed with it.

```ts
import { NebiusLLMService } from "@pipedog/nebius/llm";
```

## Prerequisites

- A Nebius account and an API key from [Nebius Token Factory](https://tokenfactory.nebius.com/).
- Pass the key as `apiKey`. It is required, and the service never falls back to
  `OPENAI_API_KEY`. The examples read it from `NEBIUS_API_KEY`.

### Settings

Runtime-updatable settings, passed as `settings: new NebiusLLMService.Settings({...})`
(`NebiusLLMSettings`). They are [OpenAI's settings](/docs/services/llm/openai#settings), with these
defaults:

| Setting | Type | Default | Description |
|---|---|---|---|
| `model` | `string` | `"Qwen/Qwen3-30B-A3B-Instruct-2507"` | Model name. |

Every other setting keeps OpenAI's default. Unset sampling settings are left out of the request, so
the provider's own defaults apply. `extra` carries provider-specific request fields.

### Notes

- Runs a completion for each `LLMContextFrame`, between an `LLMFullResponseStartFrame` and an
  `LLMFullResponseEndFrame`, and streams the reply as `LLMTextFrame`s, as
  [`OpenAILLMService`](/docs/services/llm/openai) does. Function calls, token usage metrics and
  `runInference` work the same way.
- "developer" messages are sent as "user" messages, since the API doesn't support that role (`supportsDeveloperRole` is `false`).

## Runtime notes

<RuntimeMatrix pkg="@pipedog/nebius" />

- The client is the official `openai` JS SDK (through `@pipedog/openai`), which talks through
  `fetch`. It works on Bun, Node, Deno and Cloudflare Workers.
- The deprecated `model` constructor option is not ported. Use `settings`.
- Tested against a local OpenAI-compatible mock server, not against Nebius itself.
