## Overview

OpenRouter puts one OpenAI-compatible API in front of many model providers, and routes each request to one of them.

- **`OpenRouterLLMService`**: an `OpenAILLMService` subclass with OpenRouter's base URL and default
  model.

## Installation

```bash
bun add @pipedog/openrouter
```

It depends on `@pipedog/openai`, which is installed with it.

```ts
import { OpenRouterLLMService } from "@pipedog/openrouter/llm";
```

## Prerequisites

- An OpenRouter account, with credits, and an API key from [OpenRouter](https://openrouter.ai/).
- Pass the key as `apiKey`. It is required, and the service never falls back to
  `OPENAI_API_KEY`. The examples read it from `OPENROUTER_API_KEY`.

## OpenRouterLLMService

### Configuration

The other options (`organization`, `project`, `defaultHeaders`, `serviceTier`,

| | |
|---|---|
| Base URL | `https://openrouter.ai/api/v1` |
| Default model | `openai/gpt-4.1` |
| Models to try | `openai/gpt-4.1`, `anthropic/claude-sonnet-4`. See the provider's catalog for the rest. |

### Settings

Runtime-updatable settings, passed as `settings: new OpenRouterLLMService.Settings({...})`
(`OpenRouterLLMSettings`). They are [OpenAI's settings](/docs/services/llm/openai#settings), with these
defaults:

| Setting | Type | Default | Description |
|---|---|---|---|
| `model` | `string` | `"openai/gpt-4.1"` | Model name. |
| `provider` | `OpenRouterProviderPreferences \| null` | `null` | Which upstream providers may serve the request, sent as `provider` in the request body. A plain object is converted. |

Every other setting keeps OpenAI's default. Unset sampling settings are left out of the request, so
the provider's own defaults apply. `extra` carries provider-specific request fields.

### Notes

- Runs a completion for each `LLMContextFrame`, between an `LLMFullResponseStartFrame` and an
  `LLMFullResponseEndFrame`, and streams the reply as `LLMTextFrame`s, as
  [`OpenAILLMService`](/docs/services/llm/openai) does. Function calls, token usage metrics and
  `runInference` work the same way.
- "developer" messages are sent as "user" messages, since the API doesn't support that role (`supportsDeveloperRole` is `false`).
- For Gemini models, every system message after the first is sent as a user message.
- A `provider` in `extra.extra_body` wins over the `provider` setting.

## Runtime notes

- The client is the official `openai` JS SDK (through `@pipedog/openai`), which talks through
  `fetch`. It works on Bun, Node, Deno and Cloudflare Workers.
- The deprecated `model` constructor option is not ported. Use `settings`.
- Tested against a local OpenAI-compatible mock server, not against OpenRouter itself.
