## Overview

NVIDIA NIM serves models such as Nemotron over an OpenAI-compatible API, on NVIDIA's cloud or on
your own hardware. pipedog ports both of Pipecat's NVIDIA LLM services:

- **`NvidiaLLMService`**: an [`OpenAILLMService`](/docs/services/llm/openai) subclass with NIM's
  base URL and a default Nemotron model. It turns a model's reasoning into `LLMThought*Frame`s,
  from a `reasoning_content` field or a leading `<think>` block, so TTS never reads it.
- **`NvidiaOmniLLMService`**: Nemotron Omni, which takes speech, images and video as well as text,
  and replies with text. By default it hears the user directly: it transcribes and answers each
  spoken turn in one request, in place of an STT service.

<Callout type="warn" title="Riva speech-to-text and text-to-speech are not ported yet">
  Upstream's NVIDIA package also has Riva services: `NvidiaSTTService`,
  `NvidiaSegmentedSTTService` and `NvidiaTTSService`, and SageMaker variants of them. They aren't
  ported yet. See
  [NVIDIA Riva speech-to-text](/docs/services/stt/nvidia) and
  [NVIDIA Riva text-to-speech](/docs/services/tts/nvidia). Use another TTS service with Omni.
</Callout>

## Installation

```bash
bun add @pipedog/nvidia
```

It depends on `@pipedog/openai`, which is installed with it.

```ts
import { NvidiaLLMService } from "@pipedog/nvidia/llm";
import { NvidiaOmniLLMService } from "@pipedog/nvidia/omni/llm";
```

## Prerequisites

- For NVIDIA's cloud endpoint, an API key from [build.nvidia.com](https://build.nvidia.com/),
  passed as `apiKey`. The examples read it from `NVIDIA_API_KEY`. The service logs a warning when
  it uses the cloud endpoint without a key.
- A local NIM deployment needs no key: pass its address as `baseUrl`.

### Settings

Runtime-updatable settings, passed as `settings: new NvidiaLLMService.Settings({...})`
(`NvidiaLLMSettings`). They are [OpenAI's settings](/docs/services/llm/openai#settings), with
`model` defaulting to `"nvidia/nemotron-3.5-super-vl-120b-a12b"`.

### Notes

- Runs a completion for each `LLMContextFrame` and streams the reply as `LLMTextFrame`s, as
  `OpenAILLMService` does. Function calls, token usage metrics and `runInference` work the same
  way.
- Reasoning sent in the delta's `reasoning_content` (or `reasoning`) field, as Nemotron Nano
  models do, is pushed as `LLMThoughtStartFrame`, `LLMThoughtTextFrame` and `LLMThoughtEndFrame`.
- A reply that starts with a `<think>...</think>` block, as DeepSeek-R1 and some Nemotron models
  write, has the block pushed as thought frames and only the rest sent on as text.

## NvidiaOmniLLMService

### Configuration

<auto-type-table cwd path="../../packages/nvidia/src/omni/llm.ts" name="NvidiaOmniLLMServiceOptions" />

| | |
|---|---|
| Base URL | `https://integrate.api.nvidia.com/v1` |
| Default model | `nvidia/nemotron-3-nano-omni-30b-a3b-reasoning` |
| Request timeout | 120 seconds (`requestTimeoutSecs`) |

### Settings

Passed as `settings: new NvidiaOmniLLMService.Settings({...})` (`NvidiaOmniLLMSettings`): the
`NvidiaLLMService` settings, with these defaults and additions.

| Setting | Type | Default | Description |
|---|---|---|---|
| `model` | `string` | `"nvidia/nemotron-3-nano-omni-30b-a3b-reasoning"` | Model name. |
| `temperature` | `number` | `0.6` | Sampling temperature. |
| `topP` | `number` | `0.95` | Nucleus sampling. |
| `audioResponseInstruction` | `string \| null` | `null` | Instruction sent with the user's speech in audio input mode. `null` uses `DEFAULT_AUDIO_RESPONSE_INSTRUCTION`, which asks for a `<transcript>` and a `<response>` section. A custom one should keep asking for both. |
| `minUserAudioSecs` | `number` | `0.3` | Shortest buffered utterance that starts a turn. |
| `preSpeechBufferSecs` | `number` | `0.2` | Audio kept from before the user started speaking, so the start of an utterance isn't clipped. |

### Notes

- In audio input mode the service announces itself as a realtime service, so the user aggregator
  works in realtime mode. It buffers the user's audio between turn boundaries and answers each
  spoken turn once it ends, after any turn still running.
- Omni writes what the user said in a `<transcript>` section. The service pushes it upstream as a
  `TranscriptionFrame`, which the user aggregator writes to the context, and sends only the
  `<response>` section on to TTS. Read the user's text from `on_user_turn_message_added`, not
  `on_user_turn_stopped`.
- The speech of a turn interrupted before Omni transcribed it is answered together with the user's
  next utterance.
- Context frames that need an answer (tool results, developer messages, typed user input) still
  start a completion, so the `LLMRunFrame` greeting works in both modes.
- Messages go through `NvidiaOmniLLMAdapter` (`@pipedog/nvidia/nvidia_omni_adapter`), which sends
  audio from `LLMContext.createAudioMessage()` and audio and video files from
  `LLMContext.createFileMessage()` as `audio_url` and `video_url` data URLs. "developer" messages
  are sent as "user" messages.
- `pipedog init` offers `NvidiaLLMService`, not the Omni service, as upstream's CLI does.

## Runtime notes

<RuntimeMatrix pkg="@pipedog/nvidia" />

- The client is the official `openai` JS SDK (through `@pipedog/openai`), which talks through
  `fetch`.
- The deprecated `model` constructor option is not ported. Use `settings`.
- Upstream keeps an Omni turn's audio in a Python `ContextVar`. pipedog keeps it per task instead,
  so tasks started from a turn don't inherit it. Only the turn's own request sends it, as upstream.
- Unit-tested with mocked clients (the ported upstream tests), not against NVIDIA itself.
