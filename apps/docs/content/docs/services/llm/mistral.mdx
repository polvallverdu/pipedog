## Overview

Mistral AI's chat models.

- **`MistralLLMService`**: an `OpenAILLMService` subclass with Mistral's base URL and default
  model. It uses `MistralLLMAdapter`, which rewrites the history to Mistral's rules: an assistant message after every tool message, system messages only at the start, and `prefix: true` on a trailing assistant message.

## Installation

```bash
bun add @pipedog/mistral
```

It depends on `@pipedog/openai`, which is installed with it.

```ts
import { MistralLLMService } from "@pipedog/mistral/llm";
import { MistralLLMAdapter } from "@pipedog/mistral/mistral_adapter";
```

## Prerequisites

- A Mistral account and an API key from [Mistral](https://docs.mistral.ai/api/).
- Pass the key as `apiKey`. It is required, and the service never falls back to
  `OPENAI_API_KEY`. The examples read it from `MISTRAL_API_KEY`.

### Settings

Runtime-updatable settings, passed as `settings: new MistralLLMService.Settings({...})`
(`MistralLLMSettings`). They are [OpenAI's settings](/docs/services/llm/openai#settings), with these
defaults:

| Setting | Type | Default | Description |
|---|---|---|---|
| `model` | `string` | `"mistral-small-latest"` | Model name. |

Every other setting keeps OpenAI's default. Unset sampling settings are left out of the request, so
the provider's own defaults apply. `extra` carries provider-specific request fields.

### Notes

- Runs a completion for each `LLMContextFrame`, between an `LLMFullResponseStartFrame` and an
  `LLMFullResponseEndFrame`, and streams the reply as `LLMTextFrame`s, as
  [`OpenAILLMService`](/docs/services/llm/openai) does. Function calls, token usage metrics and
  `runInference` work the same way.
- "developer" messages are sent as "user" messages, since the API doesn't support that role (`supportsDeveloperRole` is `false`).
- Messages go through `MistralLLMAdapter`, which rewrites the history to Mistral's rules: an assistant message after every tool message, system messages only at the start, and `prefix: true` on a trailing assistant message.
- `seed` is sent as Mistral's `random_seed`. `stream_options`, `max_completion_tokens` and `service_tier` are not sent.
- Mistral detects function calls from the whole history, so calls that already have a tool result in the context are skipped instead of run twice. `on_function_calls_started` may still fire twice.
- The same package has Mistral's [speech-to-text](/docs/services/stt/mistral) and [text-to-speech](/docs/services/tts/mistral) services.

## Runtime notes

- The client is the official `openai` JS SDK (through `@pipedog/openai`), which talks through
  `fetch`. It works on Bun, Node, Deno and Cloudflare Workers.
- The deprecated `model` constructor option is not ported. Use `settings`.
- Tested against a local OpenAI-compatible mock server, not against Mistral itself.
