## Overview

Cerebras serves open models with fast inference on its own hardware.

- **`CerebrasLLMService`**: an `OpenAILLMService` subclass with Cerebras's base URL and default
  model.

## Installation

```bash
bun add @pipedog/cerebras
```

It depends on `@pipedog/openai`, which is installed with it.

```ts
import { CerebrasLLMService } from "@pipedog/cerebras/llm";
```

## Prerequisites

- A Cerebras account and an API key from the [Cerebras platform](https://cloud.cerebras.ai/).
- Pass the key as `apiKey`. It is required, and the service never falls back to
  `OPENAI_API_KEY`. The examples read it from `CEREBRAS_API_KEY`.

### Settings

Runtime-updatable settings, passed as `settings: new CerebrasLLMService.Settings({...})`
(`CerebrasLLMSettings`). They are [OpenAI's settings](/docs/services/llm/openai#settings), with these
defaults:

| Setting | Type | Default | Description |
|---|---|---|---|
| `model` | `string` | `"gpt-oss-120b"` | Model name. |

Every other setting keeps OpenAI's default. Unset sampling settings are left out of the request, so
the provider's own defaults apply. `extra` carries provider-specific request fields.

### Notes

- Runs a completion for each `LLMContextFrame`, between an `LLMFullResponseStartFrame` and an
  `LLMFullResponseEndFrame`, and streams the reply as `LLMTextFrame`s, as
  [`OpenAILLMService`](/docs/services/llm/openai) does. Function calls, token usage metrics and
  `runInference` work the same way.
- "developer" messages are sent as is: the API supports that role.
- Cerebras honors `max_tokens`, `max_completion_tokens` and the penalties, so they are sent when set.

## Runtime notes

<RuntimeMatrix pkg="@pipedog/cerebras" />

- The client is the official `openai` JS SDK (through `@pipedog/openai`), which talks through
  `fetch`. It works on Bun, Node, Deno and Cloudflare Workers.
- The deprecated `model` constructor option is not ported. Use `settings`.
- Tested against a local OpenAI-compatible mock server, not against Cerebras itself.
