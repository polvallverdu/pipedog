## Overview

DeepSeek's chat models, with control over their thinking mode.

- **`DeepSeekLLMService`**: an `OpenAILLMService` subclass with DeepSeek's base URL and default
  model. It uses `DeepSeekLLMAdapter`, which adds an empty `reasoning_content` to assistant messages that have none, which DeepSeek requires in thinking mode once a tool call is involved.

## Installation

```bash
bun add @pipedog/deepseek
```

It depends on `@pipedog/openai`, which is installed with it.

```ts
import { DeepSeekLLMService } from "@pipedog/deepseek/llm";
import { DeepSeekLLMAdapter } from "@pipedog/deepseek/deepseek_adapter";
```

## Prerequisites

- A DeepSeek account and an API key from the [DeepSeek platform](https://platform.deepseek.com/).
- Pass the key as `apiKey`. It is required, and the service never falls back to
  `OPENAI_API_KEY`. The examples read it from `DEEPSEEK_API_KEY`.

### Settings

Runtime-updatable settings, passed as `settings: new DeepSeekLLMService.Settings({...})`
(`DeepSeekLLMSettings`). They are [OpenAI's settings](/docs/services/llm/openai#settings), with these
defaults:

| Setting | Type | Default | Description |
|---|---|---|---|
| `model` | `string` | `"deepseek-flash"` | Model name. |
| `thinking` | `DeepSeekThinkingConfig \| null` | `{ type: "disabled" }` | Thinking mode, sent as `thinking` in the request body. `null` leaves it to DeepSeek's default. A plain `{ type }` object is converted. |

Every other setting keeps OpenAI's default. Unset sampling settings are left out of the request, so
the provider's own defaults apply. `extra` carries provider-specific request fields.

### Notes

- Runs a completion for each `LLMContextFrame`, between an `LLMFullResponseStartFrame` and an
  `LLMFullResponseEndFrame`, and streams the reply as `LLMTextFrame`s, as
  [`OpenAILLMService`](/docs/services/llm/openai) does. Function calls, token usage metrics and
  `runInference` work the same way.
- "developer" messages are sent as "user" messages, since the API doesn't support that role (`supportsDeveloperRole` is `false`).
- Messages go through `DeepSeekLLMAdapter`, which adds an empty `reasoning_content` to assistant messages that have none, which DeepSeek requires in thinking mode once a tool call is involved.
- `seed`, `max_completion_tokens` and `service_tier` are not sent: DeepSeek doesn't support them.
- DeepSeek can't enforce a response schema (`supportsResponseSchema` is `false`), so `runInference` ignores `responseSchema`, with a warning.

## Runtime notes

- The client is the official `openai` JS SDK (through `@pipedog/openai`), which talks through
  `fetch`. It works on Bun, Node, Deno and Cloudflare Workers.
- The deprecated `model` constructor option is not ported. Use `settings`.
- Tested against a local OpenAI-compatible mock server, not against DeepSeek itself.
