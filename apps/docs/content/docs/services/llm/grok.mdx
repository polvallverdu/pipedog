## Installation

```bash
bun add @pipedog/xai
```

It depends on `@pipedog/openai`, which is installed with it.

```ts
import { GrokLLMService } from "@pipedog/xai/llm";
```

## Prerequisites

- An xAI account and an API key from the [xAI console](https://console.x.ai/).
- Pass the key as `apiKey`. It is required, and the service never falls back to
  `OPENAI_API_KEY`. The examples read it from `XAI_API_KEY`.

### Settings

Runtime-updatable settings, passed as `settings: new GrokLLMService.Settings({...})`
(`GrokLLMSettings`). They are [OpenAI's settings](/docs/services/llm/openai#settings), with these
defaults:

| Setting | Type | Default | Description |
|---|---|---|---|
| `model` | `string` | `"grok-4.20-non-reasoning"` | Model name. |
| `reasoningEffort` | `"none" \| "low" \| "medium" \| "high" \| "xhigh" \| null` | `null` | Sent as `reasoning_effort` when set, unless `extra` already has one. The non-reasoning models, including the default, reject it. |

Every other setting keeps OpenAI's default. Unset sampling settings are left out of the request, so
the provider's own defaults apply. `extra` carries provider-specific request fields.

### Notes

- Runs a completion for each `LLMContextFrame`, between an `LLMFullResponseStartFrame` and an
  `LLMFullResponseEndFrame`, and streams the reply as `LLMTextFrame`s, as
  [`OpenAILLMService`](/docs/services/llm/openai) does. Function calls, token usage metrics and
  `runInference` work the same way.
- "developer" messages are sent as is: the API supports that role.
- xAI reports reasoning tokens apart from `completion_tokens`, so they are added to the completion count in token usage metrics when the total says so.
- `@pipedog/grok` re-exports `GrokLLMService` from `@pipedog/xai/llm`, as upstream's deprecated `pipecat.services.grok.llm` does. Import from `@pipedog/xai/llm`.
- The same package has xAI's [speech-to-text](/docs/services/stt/xai) and [text-to-speech](/docs/services/tts/xai) services. The Grok realtime (speech-to-speech) service isn't ported yet.

## Runtime notes

- The client is the official `openai` JS SDK (through `@pipedog/openai`), which talks through
  `fetch`. It works on Bun, Node, Deno and Cloudflare Workers.
- The deprecated `model` constructor option is not ported. Use `settings`.
- Tested against a local OpenAI-compatible mock server, not against xAI Grok itself.
