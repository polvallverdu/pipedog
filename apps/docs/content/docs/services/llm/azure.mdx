## Overview

- **`AzureLLMService`**: OpenAI chat models deployed in Azure AI Foundry (Azure OpenAI). It
  extends [`OpenAILLMService`](/docs/services/llm/openai), so streaming, function calling, token
  usage metrics and `runInference` work the same way; only the client differs.

The shape of `endpoint` picks the API surface:

- An endpoint ending in **`/openai/v1`** uses Azure's v1 API, which tracks new features and
  needs no `api-version`. This is the one to use.
- Any other endpoint (for example `https://my-resource.openai.azure.com`) goes through the dated
  API, with `api-version=2025-04-01-preview`, the last dated version Azure issued.

Both surfaces accept an API key or a Microsoft Entra ID token.

## Installation

```bash
bun add @pipedog/azure
```

```ts
import { AzureLLMService } from "@pipedog/azure/llm";
```

`@pipedog/azure` depends on `@pipedog/openai` and the `openai` SDK, which it installs for you.

## Prerequisites

- An Azure OpenAI (or Azure AI Foundry) resource with a chat model deployed. The deployment
  name is what you pass as `model`.
- The resource's endpoint, and either its API key or a Microsoft Entra ID identity with access
  to it. The examples read the key from `AZURE_OPENAI_API_KEY`.

### Notes

- On the v1 surface the client is the plain `OpenAI` client pointed at the endpoint, with the
  key (or the token provider) as its API key. On the dated surface it is the SDK's `AzureOpenAI`
  client, which sends the key in the `api-key` header, adds `api-version`, and routes to
  `/openai/deployments/<model>/...`.
- `apiKey` or `tokenProvider` is required; the constructor throws without either. With both,
  the token provider is used.
- Event handlers, frames and metrics are those of `OpenAILLMService`.

## Runtime notes

<RuntimeMatrix pkg="@pipedog/azure" />

- The client is the official `openai` JS SDK over `fetch`, so the service works on Bun, Node,
  Deno and Cloudflare Workers.
- `AzureTokenProvider` is any `() => Promise<string>`. `getBearerTokenProvider()` from
  `@azure/identity` returns one; on Workers, where `@azure/identity`'s credentials don't run,
  fetch the token yourself (for example through a client-credentials request to Entra ID).
- The deprecated `model` and `apiVersion` constructor options are not ported. Use `settings`
  for the model, and an `/openai/v1` endpoint instead of a dated version.
