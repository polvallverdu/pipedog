## Overview

Sarvam AI's models for Indian languages, over an OpenAI-compatible API (`sarvam-105b`, plus a few hosted open models).

- **`SarvamLLMService`**: an `OpenAILLMService` subclass with Sarvam AI's base URL and default
  model.

## Installation

```bash
bun add @pipedog/sarvam
```

It depends on `@pipedog/openai`, which is installed with it.

```ts
import { SarvamLLMService } from "@pipedog/sarvam/llm";
```

## Prerequisites

- A Sarvam account and an API key from the [Sarvam dashboard](https://dashboard.sarvam.ai/).
- Pass the key as `apiKey`. It is required, and the service never falls back to
  `OPENAI_API_KEY`. The examples read it from `SARVAM_API_KEY`.

### Settings

Runtime-updatable settings, passed as `settings: new SarvamLLMService.Settings({...})`
(`SarvamLLMSettings`). They are [OpenAI's settings](/docs/services/llm/openai#settings), with these
defaults:

| Setting | Type | Default | Description |
|---|---|---|---|
| `model` | `string` | `"sarvam-105b"` | Model name. |
| `wikiGrounding` | `boolean \| null` | `null` | Sent as `wiki_grounding` when set. Only `sarvam-105b` and `gemma4` support it. |
| `reasoningEffort` | `"low" \| "medium" \| "high" \| null` | `null` | Sent as `reasoning_effort` when set, on the models that reason. |

Every other setting keeps OpenAI's default. Unset sampling settings are left out of the request, so
the provider's own defaults apply. `extra` carries provider-specific request fields.

### Notes

- Runs a completion for each `LLMContextFrame`, between an `LLMFullResponseStartFrame` and an
  `LLMFullResponseEndFrame`, and streams the reply as `LLMTextFrame`s, as
  [`OpenAILLMService`](/docs/services/llm/openai) does. Function calls, token usage metrics and
  `runInference` work the same way.
- "developer" messages are sent as "user" messages, since the API doesn't support that role (`supportsDeveloperRole` is `false`).
- Only `deepseekv4.1-flash`, `gemma4`, `glm5.3`, `sarvam-105b` and `sarvam-105b-conversations` are accepted as the model. Any other raises when the service is constructed.
- When you don't pass `baseUrl`, it is chosen from the model: `/v1` for `sarvam-105b-conversations` and `/v2` for the rest.
- A context that a model can't serve (an image for a model without vision, say) fails with a non-fatal `ErrorFrame`, not an exception, so an `LLMSwitcher` can fall back to another service.
- The same package has Sarvam's [speech-to-text](/docs/services/stt/sarvam) and [text-to-speech](/docs/services/tts/sarvam) services.

## Runtime notes

- The client is the official `openai` JS SDK (through `@pipedog/openai`), which talks through
  `fetch`. It works on Bun, Node, Deno and Cloudflare Workers.
- The deprecated `model` constructor option is not ported. Use `settings`.
- Tested against a local OpenAI-compatible mock server, not against Sarvam AI itself.
