## Overview

`AWSBedrockLLMService` runs any Bedrock model that supports the Converse API. It streams text
with ConverseStream, calls functions, supports prompt caching and reasoning effort, and reports
token usage, including cache tokens.

- **`AWSBedrockLLMService`**: the LLM service, with `AWSBedrockLLMSettings` for runtime-updatable
  settings.
- **`AWSBedrockLLMAdapter`**: converts the universal `LLMContext` and tools to Converse messages,
  `system` blocks and `toolConfig`.

## Installation

```bash
bun add @pipedog/aws
```

```ts
import { AWSBedrockLLMService } from "@pipedog/aws/llm";
```

No AWS SDK is needed: the service calls the Bedrock REST API with `fetch`, signed with SigV4.

## Prerequisites

- An AWS account with access to the model in the Bedrock console, in the region you use.
- An IAM identity allowed `bedrock:InvokeModel` and `bedrock:InvokeModelWithResponseStream`.
- Keys, in this order of precedence:
  1. `awsAccessKey`, `awsSecretKey` and `awsSessionToken`.
  2. The `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` and `AWS_SESSION_TOKEN` environment
     variables.
  3. A `credentialsProvider` function, called for every request.

  The region comes from `awsRegion`, else `AWS_REGION`, else `us-east-1`.

### Settings

Runtime-updatable settings, passed as `settings: new AWSBedrockLLMService.Settings({...})`. Any
setting you leave out keeps the default below. `null` means the field is not sent.

| Setting | Type | Default | Description |
|---|---|---|---|
| `model` | `string` | `"us.amazon.nova-lite-v1:0"` | Bedrock model ID or inference profile. |
| `systemInstruction` | `string \| null` | `null` | System prompt, sent as a `system` block. |
| `maxTokens` | `number \| null` | `null` | `inferenceConfig.maxTokens`. |
| `temperature` | `number \| null` | `null` | `inferenceConfig.temperature`. |
| `topP` | `number \| null` | `null` | `inferenceConfig.topP`. |
| `stopSequences` | `string[] \| null` | `null` | `inferenceConfig.stopSequences`. |
| `latency` | `"standard" \| "optimized" \| null` | `null` | `performanceConfig.latency`. |
| `effort` | `string \| null` | `null` | `outputConfig.effort` for reasoning models (`"low"` to `"max"`). |
| `enablePromptCaching` | `boolean` | `false` | Add `cachePoint` markers to the system prompt and tools. |
| `additionalModelRequestFields` | `Record<string, unknown>` | `{}` | Model-specific fields, sent as `additionalModelRequestFields`. |

### Notes

- Consumes `LLMContextFrame` and emits `LLMFullResponseStartFrame`, `LLMTextFrame`s and
  `LLMFullResponseEndFrame`.
- When the context has tool calls in its history but no tools are configured, the service sends
  a no-op tool, because Bedrock rejects tool messages without a `toolConfig`.
- For Claude models that reject assistant prefill, a trailing user message is added when the
  context ends with an assistant message.
- `runInference` uses Converse (not streaming). Converse has no reply schema, so a
  `responseSchema` is accepted but not enforced.
- With `retryOnTimeout: true`, the first attempt is limited to `retryTimeoutSecs` (5 by default).
  If it times out, the request is retried once with no timeout.
- Errors are `AWSServiceError`s with the AWS error code (`ThrottlingException`,
  `ValidationException`, …) and the HTTP status. An exception sent inside the event stream has
  status 0.

## Runtime notes

- Runs on Bun, Node, Deno and Cloudflare Workers: requests are signed with SigV4 on WebCrypto,
  and the `application/vnd.amazon.eventstream` response is decoded in the package.
- There is no default AWS credential chain (profiles, IMDS, ECS roles, SSO). Use the keys, the
  environment, or `credentialsProvider`.
- botocore's `client_config` is not ported, so there are no client-side retries of throttled or
  5xx requests and no 300 s timeouts. Pass your own `fetch` to add them.
- `endpointUrl` sends requests to another host (a VPC endpoint or a local fake); `fetch` replaces
  the global `fetch`.
- Not ported: the deprecated `AWSBedrockLLMService.InputParams` and the `model`, `params` and
  `stopSequences` constructor arguments. Use `settings`.
