## Overview

HeyGen renders a talking avatar from your bot's speech. The session is controlled over HTTP and a
WebSocket, and the avatar's video and audio travel through a LiveKit room. There are two ways to
use it:

- **`HeyGenVideoService`** (`@pipedog/heygen`): a pipeline service placed after your TTS. It sends
  the TTS audio to the avatar and pushes the avatar's video (`OutputImageRawFrame`) and audio
  (`SpeechOutputAudioRawFrame`) downstream, so any output transport can deliver them to the user.
- **`HeyGenTransport`** (`@pipedog/transport-heygen`): the bot joins the avatar's LiveKit room as
  a participant. The user joins the same room and sees the avatar directly; the bot hears the user
  and sends its speech to the avatar.

Both talk to **LiveAvatar** (`ServiceType.LIVE_AVATAR`, `api.liveavatar.com`) or to HeyGen's older
**Interactive Avatar** streaming API (`ServiceType.INTERACTIVE_AVATAR`, `api.heygen.com`, the
default for backwards compatibility).

## Runtimes

| | Bun | Node ≥ 22 | Deno | Cloudflare Workers |
|---|---|---|---|---|
| `LiveAvatarApi`, `HeyGenApi` (session HTTP APIs) | ✅ | ✅ | ✅ | not verified |
| `HeyGenClient` control WebSocket | ✅ | ✅ | ✅ | not verified |
| `HeyGenVideoService`, `HeyGenTransport` (avatar media) | ✅ | ✅ | ✅ (`--allow-all`) | ❌ |

The session APIs use only `fetch` and the control channel only `WebSocket`, so they have no
runtime requirements of their own, but the packages aren't tested on Workers. The media goes
through LiveKit's native Node SDK, `@livekit/rtc-node`, which loads a native N-API addon. Workers
can't load native code, so the service and the transport don't run there. Importing the packages
works everywhere: the addon is only loaded when the client sets up.

## Installation

```bash
bun add @pipedog/heygen @livekit/rtc-node
# and, for the transport:
bun add @pipedog/transport-heygen
```

```ts
import { HeyGenVideoService } from "@pipedog/heygen/video";
import { HeyGenTransport, HeyGenParams } from "@pipedog/transport-heygen/transport";
import { LiveAvatarNewSessionRequest } from "@pipedog/heygen/api_liveavatar";
import { ServiceType } from "@pipedog/heygen/client";
```

`@livekit/rtc-node` is an optional peer dependency: install it yourself (version 1.1.0 or newer in
the 1.x line). It ships prebuilt binaries for these platforms only:

| OS | Architectures |
|---|---|
| macOS | arm64 (`darwin-arm64`), x64 (`darwin-x64`) |
| Linux with glibc | x64 (`linux-x64-gnu`), arm64 (`linux-arm64-gnu`) |
| Windows | x64 (`win32-x64-msvc`) |

There is no build for musl (Alpine Linux): use a Debian- or Ubuntu-based image. Without the
package, or on another platform, joining the room fails with an error that says how to install
it.

## Prerequisites

- A **LiveAvatar account** and its API key (for `ServiceType.LIVE_AVATAR`; see
  [LiveAvatar's docs](https://docs.liveavatar.com)), or a **HeyGen account** and API key for the
  Interactive Avatar API. Pass it as `apiKey`; the samples read `HEYGEN_LIVE_AVATAR_API_KEY`.
- An avatar ID (`avatarId`). Without a session request, the client uses upstream's default public
  avatar for the chosen API.
- No LiveKit server of your own: HeyGen hosts the room and returns its URL and tokens. To use your
  own LiveKit server or LiveKit Cloud instead, pass a `CustomSDKLiveKitConfig` as `livekitConfig`.
- A long-running Bun, Node or Deno process on one of the platforms above.

### Notes

- TTS audio is resampled to 24 kHz and sent as `agent.speak` messages: a 400 ms first chunk, then
  1 s chunks. When no audio arrives for 0.35 s, the rest is flushed and `agent.speak_end` sent.
- A `UserStartedSpeakingFrame` interrupts the avatar (`agent.interrupt`) and starts its listening
  animation; `UserStoppedSpeakingFrame` stops it.
- The service joins the room with the user's token (`connectAsUser`), so HeyGen doesn't end the
  session after five minutes without a user.

## Runtime notes

- The session APIs use `fetch`; pass `fetch` to replace the global one (upstream takes an aiohttp
  session).
- The control WebSocket uses the global `WebSocket`. `clientOptions.websocketOptions` takes a
  `webSocketFactory` for runtimes that open sockets differently.
- LiveAvatar's API documents `livekit_agent_token` and `ws_url` as optional. Upstream requires
  them; here a session without a WebSocket URL runs without avatar control (logged as a warning),
  and one without an agent token joins the room with the client token.
- Callbacks given to `HeyGenClient.captureParticipantAudio` and `captureParticipantVideo` receive
  the frame fields (`audio`, `sampleRate`, `numChannels` / `image`, `size`, `format`) rather than
  an `AudioRawFrame` or `ImageRawFrame` instance.
