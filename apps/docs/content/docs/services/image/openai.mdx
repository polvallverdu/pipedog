## Overview

- **`OpenAIImageGenService`**: turns each `TextFrame` it receives into a prompt for OpenAI's
  Images API (`images.generate`) and pushes the result as a `URLImageRawFrame` of RGB pixels.

## Installation

```bash
bun add @pipedog/openai
```

```ts
import { OpenAIImageGenService } from "@pipedog/openai/image";
```

## Prerequisites

- An OpenAI account and an API key from the [OpenAI dashboard](https://platform.openai.com/api-keys).
- Pass the key as `apiKey` (required). The examples read it from `OPENAI_API_KEY`.

### Settings

Runtime-updatable settings, passed as `settings: new OpenAIImageGenService.Settings({...})`
(`OpenAIImageGenSettings`). Any setting you leave out keeps the default below.

| Setting | Type | Default | Description |
|---|---|---|---|
| `model` | `string` | `"gpt-image-2.5-flare"` | Image model. |
| `imageSize` | `OpenAIImageSize \| string \| null` | `null` | `"auto"`, `"1024x1024"`, `"1536x1024"`, `"1024x1536"`, ... `null` leaves it to OpenAI. |
| `quality` | `OpenAIImageQuality \| string \| null` | `null` | `"auto"`, `"low"`, `"medium"`, `"high"`, ... Lower is faster. `null` lets OpenAI pick. |
| `moderation` | `OpenAIImageModeration \| string \| null` | `null` | Content-moderation level for generated images: `"low"` for less restrictive filtering, or `"auto"`. `null` leaves OpenAI's default. |

### Notes

- Each `TextFrame` is pushed on downstream, then used as the prompt. One image is generated per
  prompt (`n: 1`).
- The GPT Image models return the image inline (base64). When the response carries a URL
  instead, the image is downloaded with `fetch` (the global one, or the `fetch` option) and the
  URL is set on the frame.
- The image is decoded to RGB (alpha dropped) with `decodePngToRgb`, a pure JS PNG decoder. Pass
  `decodeImage` to decode other formats.
- A response with no image data produces an `ErrorFrame`.
- As upstream, the constructor passes only `settings` to the base service, so the inherited
  frame processor options (such as `name`) have no effect.

## Runtime notes

<RuntimeMatrix pkg="@pipedog/openai" />

- The client is the `openai` JS SDK over `fetch`, and decoding is pure JS (`fast-png`), so it
  works on Bun, Node, Deno and Cloudflare Workers.
- The `fetch` option replaces upstream's required `aiohttp_session`. `decodeImage` is a pipedog
  addition; upstream decodes with Pillow.
- The deprecated `imageSize` and `model` constructor options are not ported. Use `settings`.
- For Azure OpenAI image generation, see [`AzureImageGenServiceREST`](/docs/services/image/azure).
