## Overview

- **`UltravoxRealtimeLLMService`**: an Ultravox Realtime call. The service creates the call over
  the Ultravox REST API (or joins one by URL) and streams audio both ways over its WebSocket.
  Ultravox is an audio-native model: it hears the user directly and answers with audio or text.
  It replaces the STT, LLM and TTS services in a pipeline, and supports function calling,
  including async tools.


## Prerequisites

- An Ultravox account and an API key from the [Ultravox console](https://app.ultravox.ai).
- Pass the key in the params (`apiKey`); it is sent as the `X-Api-Key` header when the call is
  created. The examples read it from `ULTRAVOX_API_KEY`. Joining by URL needs no key.

## UltravoxRealtimeLLMService

### Configuration

<auto-type-table cwd path="../../packages/ultravox/src/llm.ts" name="UltravoxRealtimeLLMServiceOptions" />

`params` picks how the call starts:

- **`OneShotInputParams`**: a one-off call with its own `systemPrompt`, `temperature`, `model`,
  `voice`, `metadata`, `outputMedium`, `maxDuration` (seconds, 10 to 3600, default one hour) and
  `extra` call parameters. Tools come from `oneShotSelectedTools`.
- **`AgentInputParams`**: a call with an agent from the Ultravox console (`agentId`), with
  `templateContext`, `metadata`, `outputMedium`, `maxDuration` and `extra`.
- **`JoinUrlInputParams`**: join a call you created yourself, by its `joinUrl`.

<auto-type-table cwd path="../../packages/ultravox/src/llm.ts" name="OneShotInputParamsOptions" />

### Settings

Runtime-updatable settings, passed as `settings: new UltravoxRealtimeLLMService.Settings({...})`
(`UltravoxRealtimeLLMSettings`).

| Setting | Type | Default | Description |
|---|---|---|---|
| `outputMedium` | `string \| null` | `null` | `"voice"` or `"text"`. A change is sent to the call as `set_output_medium`. |
| `model`, `systemInstruction`, `temperature`, ... | | `null` | Set in `params` instead; changing them at runtime is ignored with a warning. |

### Notes

- Consumes `InputAudioRawFrame` (resampled to 48 kHz and sent as binary), `LLMContextFrame`
  (new user text goes in as `user_text_message`) and `InterruptionFrame`. Emits
  `TTSAudioRawFrame` at 48 kHz, `TTSTextFrame` and `LLMTextFrame` for the bot, and
  `TranscriptionFrame` for the user. Transcripts of the user are Ultravox's and may not match
  what the audio-native model understood.
- When Ultravox clears its playback buffer (the user barged in), the service broadcasts an
  `InterruptionFrame`.
- It does not emit `UserStartedSpeakingFrame` / `UserStoppedSpeakingFrame`; Ultravox decides
  turns on the server. To get local turn frames, add a VAD to the user aggregator.
  `LLMContextAggregatorPair` detects that this is a realtime service either way.
- An async tool (`cancelOnInterruption: false`) gets a placeholder result as soon as Ultravox
  calls it; its real result, and any intermediate results, go to the model as user text.

## Runtime notes

- Calls are created with `fetch` (upstream uses aiohttp) and the socket is opened with
  `websocketConnect()` from core, so the service runs on Bun, Node, Deno and Cloudflare Workers.
- `maxDuration` is in seconds (upstream takes a `timedelta`); out-of-range values throw a
  `RangeError` from the params constructor.
