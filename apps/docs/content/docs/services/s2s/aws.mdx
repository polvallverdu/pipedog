## Overview

`AWSNovaSonicLLMService` streams the user's audio to Amazon Nova Sonic on Bedrock
(`InvokeModelWithBidirectionalStream`) and returns spoken audio, transcripts and tool calls, so
one service replaces the STT, LLM and TTS stages of a pipeline.

- **`AWSNovaSonicLLMService`**: the session, with `AWSNovaSonicLLMSettings` and `AudioConfig`.
- **`AWSNovaSonicLLMAdapter`**: converts the `LLMContext` history and tools to Nova Sonic's
  events.
- **`SessionContinuationParams`**: hands the conversation to a new session before Nova Sonic's
  session time limit, buffering audio so nothing is lost.

## Installation

```bash
bun add @pipedog/aws
```

```ts
import { AudioConfig, AWSNovaSonicLLMService } from "@pipedog/aws/nova_sonic/llm";
```

The default transport needs no AWS SDK. For `transport: "http2"`, also install
`@aws-sdk/client-bedrock-runtime` (an optional peer dependency).

## Prerequisites

- Access to Nova Sonic in the Bedrock console, in a region that offers it.
- An IAM identity allowed `bedrock:InvokeModelWithBidirectionalStream`.
- Keys, in this order of precedence:
  1. `accessKeyId`, `secretAccessKey` and `sessionToken`.
  2. The `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` and `AWS_SESSION_TOKEN` environment
     variables.
  3. A `credentialsProvider` function, called for every new session.

  The region comes from `region`, else `AWS_REGION`, else `us-east-1`.

### Settings

Runtime-updatable settings, passed as `settings: new AWSNovaSonicLLMService.Settings({...})`.

| Setting | Type | Default | Description |
|---|---|---|---|
| `model` | `string` | `"amazon.nova-2-5-sonic"` | Bedrock model ID. |
| `voice` | `string` | `"matthew"` | Voice ID. |
| `systemInstruction` | `string \| null` | `null` | System prompt, sent when the session starts. |
| `temperature` | `number` | `0.7` | Sampling temperature. |
| `maxTokens` | `number` | `1024` | Maximum tokens per response. |
| `topP` | `number` | `0.9` | Top-p sampling. |
| `endpointingSensitivity` | `"LOW" \| "MEDIUM" \| "HIGH" \| null` | `null` | How quickly Nova Sonic decides the user stopped speaking. |

### Notes

- Nova Sonic detects turns itself. User and bot transcripts are pushed as transcription and
  `LLMTextFrame`s, and audio as `TTSAudioRawFrame`s.
- Tools from the context (or `tools`) are sent when the session starts. Tool calls run through
  the usual function-call flow, and results go back as `toolResult` events.
- With `sessionContinuation`, a new session is opened ahead of the time limit
  (`transitionThresholdSeconds`) and takes over at the next turn boundary, with the conversation
  history and buffered user audio.
- The JSON events on the wire are upstream's, character for character. Float settings use JS
  formatting, so `1.0` is sent as `1`.

## Runtime notes

<RuntimeMatrix pkg="@pipedog/aws" />

- The default transport is Bedrock's WebSocket endpoint for `InvokeModelWithBidirectionalStream`,
  the one the AWS SDK for JavaScript uses in browsers. pipedog presigns the URL and signs each
  event with SigV4 on WebCrypto, so it runs on Bun, Node, Deno and Cloudflare Workers.
- `transport: "http2"` loads `@aws-sdk/client-bedrock-runtime` on connect and uses Node's
  `http2`, as upstream does: Node and Bun only.
- `clientFactory` replaces the stream client entirely (for tests or another transport), and
  `endpointUrl` changes the host.
- Upstream requires the keys; here they are optional, with the environment and
  `credentialsProvider` as fallbacks.
- Not ported: the deprecated `Params` class and the `model`, `voiceId`, `params` and
  `systemInstruction` constructor options. Use `settings` and `audioConfig`.
