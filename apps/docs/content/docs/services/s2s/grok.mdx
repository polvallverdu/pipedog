## Overview

- **`GrokRealtimeLLMService`**: one WebSocket session with xAI's Grok Voice Agent API, which
  hears the user's audio and answers with audio. It replaces the STT, LLM and TTS services in a
  pipeline, and supports function calling, xAI's built-in tools (web search, X search, file
  search, remote MCP), transcripts of both sides, DTMF on SIP sessions and fixed spoken lines.

## Installation

```bash
bun add @pipedog/xai
```

```ts
import { GrokRealtimeLLMService } from "@pipedog/xai/realtime/llm";
import { SessionProperties } from "@pipedog/xai/realtime/events";
```

`@pipedog/xai/realtime/events` holds the session classes (`SessionProperties`,
`AudioConfiguration`, `AudioInput`, `AudioOutput`, `InputAudioTranscription`, `TurnDetection`,
`Reasoning`, `SessionResumption`), the tools (`WebSearchTool`, `XSearchTool`, `FileSearchTool`,
`FunctionTool`, `McpTool`) and the client and server event models.

## Prerequisites

- An xAI account and an API key from the [xAI console](https://console.x.ai).
- Pass the key as `apiKey` (required); it is sent as a bearer token. The examples read it from
  `XAI_API_KEY`.

### Settings

Runtime-updatable settings, passed as `settings: new GrokRealtimeLLMService.Settings({...})`
(`GrokRealtimeLLMSettings`). Any setting you leave out keeps the default below.

| Setting | Type | Default | Description |
|---|---|---|---|
| `model` | `string` | `"grok-voice-latest"` | Voice model. Fixed for the session: it goes in the connection URL. |
| `systemInstruction` | `string \| null` | `null` | Instructions. Kept in sync with `sessionProperties.instructions`. |
| `sessionProperties` | `SessionProperties` | `new SessionProperties()` | Session config: `voice` (default `"eve"`), `turnDetection` (default server VAD), audio, tools, reasoning, resumption, pronunciation `replace` map. |
| `temperature`, `maxTokens`, `topP`, `topK`, `frequencyPenalty`, `presencePenalty`, `seed` | `number \| null` | `null` | Not used by the Voice Agent API. |
| `filterIncompleteUserTurns` | `boolean` | `false` | Filter incomplete user turns. |
| `userTurnCompletionConfig` | `UserTurnCompletionConfig \| null` | `null` | Turn completion config used with `filterIncompleteUserTurns`. |

A `sessionProperties` in an update replaces the stored one as a whole. The top-level
`systemInstruction` wins over `instructions` inside it. Audio formats default to PCM at the
pipeline's rates.

### Event handlers

| Event | Description |
|---|---|
| `on_conversation_item_created` | A conversation item was added. Called with the item id and the item. |
| `on_conversation_item_updated` | A conversation item changed (a transcript arrived, or the response finished). Called with the item id and the item, or `null`. |
| `on_conversation_item_deleted` | The server confirmed a deletion. Called with the item id. |
| `on_conversation_item_truncated` | The server confirmed a truncation. Called with the item id, content index and audio end (ms). |
| `on_idle_timeout` | `turnDetection.idleTimeoutMs` fired and the server is checking in. Called with the item id. |
| `on_dtmf_received` | A DTMF digit arrived on a SIP session. Called with the `KeypadEntry`. |
| `on_mcp_event` | An MCP tool discovery or call event. Called with the event type and the event. |

### Notes

- Consumes `InputAudioRawFrame` (sent once the session is configured), `LLMContextFrame`,
  `LLMMessagesAppendFrame` and `LLMSetToolsFrame`. Emits `TTSAudioRawFrame`, `TTSTextFrame` and
  `LLMTextFrame` for the bot, `InterimTranscriptionFrame` (with `grok-transcribe`) and
  `TranscriptionFrame` for the user, and `InputDTMFFrame` upstream for DTMF digits.
- With server-side VAD (the default), the service broadcasts proposed user turn frames from the
  server's speech events and asks the user aggregator for `ExternalUserTurnStrategies`, so no
  local VAD is needed. On interruption it cancels the response and truncates the assistant audio
  to what was played.
- For locally driven turns, set `turnDetection: null` in `SessionProperties` and add a VAD to the
  user aggregator; the service then commits the audio and asks for a response when the user stops
  speaking.
- Intermediate tool results (`isFinal: false`) go in as conversation messages beside the open
  call; the final result answers the call.
- `forceMessage()`, `deleteConversationItem()`, `setAudioInputPaused()`, `sendClientEvent()` and
  `resetConversation()` are available at runtime.

## Runtime notes

<RuntimeMatrix pkg="@pipedog/xai" />

- The socket is opened with `websocketConnect()` from core, with the key in the `Authorization`
  header. Bun, Node and Deno send it from the global `WebSocket`; on Cloudflare Workers core opens
  the socket through `fetch`.
- The deprecated `sessionProperties` constructor option and the `pipecat.services.grok.realtime`
  aliases are not ported: import from `@pipedog/xai/realtime/*` and pass `sessionProperties` in
  `settings`.
- A failed response whose `status_details` isn't a string is reported as JSON (upstream prints a
  Python dict).
