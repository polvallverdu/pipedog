## Overview

- **`InworldRealtimeLLMService`**: one WebSocket session with Inworld's Realtime API, which hears
  the user's audio and answers with audio. Under the hood Inworld runs STT, an LLM of your choice
  (for example `openai/gpt-4.1-mini`) and Inworld TTS, with semantic server-side turn detection.
  It replaces the STT, LLM and TTS services in a pipeline, and supports function calling and
  transcripts of both sides.

## Installation

```bash
bun add @pipedog/inworld
```

```ts
import { InworldRealtimeLLMService } from "@pipedog/inworld/realtime/llm";
import { SessionProperties } from "@pipedog/inworld/realtime/events";
```

`@pipedog/inworld/realtime/events` holds the session classes (`SessionProperties`,
`AudioConfiguration`, `AudioInput`, `AudioOutput`, `InputTranscription`, `TurnDetection`,
`PCMAudioFormat`, ...) and the client and server event models.

## Prerequisites

- An Inworld account and an API key from the [Inworld portal](https://platform.inworld.ai).
- Pass the key as `apiKey` (required). With the default `authType: "basic"` it is sent as
  `Authorization: Basic <apiKey>` (the Base64 key Inworld gives you). Use `authType: "bearer"`
  for a client-side JWT. The examples read it from `INWORLD_API_KEY`.

### Settings

Runtime-updatable settings, passed as `settings: new InworldRealtimeLLMService.Settings({...})`
(`InworldRealtimeLLMSettings`). Any setting you leave out keeps the default below.

| Setting | Type | Default | Description |
|---|---|---|---|
| `model` | `string` | `llmModel`, or `"openai/gpt-4.1-mini"` | The LLM Inworld runs. Kept in sync with `sessionProperties.model`. |
| `systemInstruction` | `string \| null` | `null` | Instructions. Kept in sync with `sessionProperties.instructions`. |
| `temperature` | `number \| null` | `null` | Sampling temperature. Kept in sync with `sessionProperties.temperature`. |
| `sessionProperties` | `SessionProperties` | see below | Session config: output modalities, audio input and output, tools. |
| `maxTokens`, `topP`, `topK`, `frequencyPenalty`, `presencePenalty`, `seed` | `number \| null` | `null` | Not used by the Realtime API. |
| `filterIncompleteUserTurns` | `boolean` | `false` | Filter incomplete user turns. |
| `userTurnCompletionConfig` | `UserTurnCompletionConfig \| null` | `null` | Turn completion config used with `filterIncompleteUserTurns`. |

The default session has output modalities `["audio", "text"]`, PCM audio both ways (the rates
follow the pipeline's), transcription with `sttModel` (default `"inworld/inworld-stt-1"`),
semantic turn detection with low eagerness that creates and interrupts responses, and the
`voice` (default `"Clive"`) and `ttsModel` (default `"inworld-tts-2"`) for output.

A `sessionProperties` you pass **replaces** those defaults as a whole, so give a complete config.
Top-level `model`, `systemInstruction` and `temperature` win over the same fields inside it.

### Event handlers

| Event | Description |
|---|---|
| `on_conversation_item_created` | A conversation item was added. Called with the item id and the item. |
| `on_conversation_item_updated` | A conversation item changed (a transcript arrived, or the response finished). Called with the item id and the item, or `null`. |

### Notes

- Consumes `InputAudioRawFrame` (sent in about 60 ms chunks), `LLMContextFrame` and
  `LLMSetToolsFrame`. Emits `TTSAudioRawFrame`, `TTSTextFrame` and `LLMTextFrame` for the bot,
  and `InterimTranscriptionFrame` / `TranscriptionFrame` for the user.
- With Inworld's server-side turn detection (the default), the service broadcasts proposed user
  turn frames from the server's speech events and asks the user aggregator for
  `ExternalUserTurnStrategies`, so no local VAD is needed. `LLMContextAggregatorPair` detects
  that this is a realtime service.
- For locally driven turns, set `turnDetection: null` in `AudioInput` and add a VAD to the user
  aggregator; the service then commits the audio and asks for a response when the user stops
  speaking. Don't run a local VAD with server-side turn detection on: both would send turn frames.
- Tool results are sent as `function_call_output` items. Intermediate results
  (`isFinal: false`) are dropped with a warning: Inworld's model calls the tool again instead of
  relaying them. `cancelOnInterruption: false` isn't reliably supported by Inworld, and the
  service reports an error when it sees one. `LLMMessagesAppendFrame` isn't supported yet.
- `setAudioInputPaused()` pauses input at runtime, `sendClientEvent()` sends any Realtime client
  event, and `resetConversation()` reconnects with a fresh server-side conversation.

## Runtime notes

- The socket is opened with `websocketConnect()` from core, with the key in the `Authorization`
  header and a fresh session `key` in the URL. Bun, Node and Deno send the header from the global
  `WebSocket`; on Cloudflare Workers core opens the socket through `fetch`.
- A failed response whose `status_details` isn't a string is reported as JSON (upstream prints a
  Python dict).
