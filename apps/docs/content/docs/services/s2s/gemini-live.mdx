## Overview

`GeminiLiveLLMService` connects to the Gemini Live API over a WebSocket. It takes user audio
(and text and video), and returns spoken audio, transcripts and tool calls, so one service
replaces the STT, LLM and TTS stages of a pipeline.

- **`GeminiLiveLLMService`**: the Live session, with server-side or local VAD, function calling,
  thinking, context window compression, session resumption and Google Search grounding.
- **`GeminiVADParams`** and **`ContextWindowCompressionParams`**: settings objects for VAD and
  compression.
- **`GeminiFileAPI`**: a client for the Gemini File API (upload, get, list, delete), available
  as `llm.fileApi`.

For Vertex AI, see [Gemini Live on Vertex AI](/docs/services/s2s/gemini-live-vertex).

### Settings

Passed as `settings: new GeminiLiveLLMService.Settings({...})`. They are sent when the session
connects. Changing them later stores the new values but doesn't apply them to the open session
(a warning names the settings that didn't take effect).

| Setting | Type | Default | Description |
|---|---|---|---|
| `model` | `string` | `"models/gemini-3.8-live"` | Gemini Live model. |
| `voice` | `string` | `"Charon"` | Voice name. |
| `language` | `Language \| string` | `"en-US"` | Language. A `Language` value is sent as Gemini's locale code (`Language.ES` as `"es-ES"`). |
| `modalities` | `GeminiModalities` | `GeminiModalities.AUDIO` | Response modality. `TEXT` logs a warning: recent models may not support it. |
| `mediaResolution` | `GeminiMediaResolution` | `GeminiMediaResolution.UNSPECIFIED` | Video input resolution. |
| `vad` | `GeminiVADParams \| null` | `null` (server VAD on) | Voice activity detection. |
| `turnCoverage` | `TurnCoverage \| null` | `null` (model default) | Which realtime input a user turn covers. |
| `contextWindowCompression` | `ContextWindowCompressionParams` | `{}` (off) | Context window compression. |
| `thinking` | `ThinkingConfig` | `{}` | Thinking configuration. Thinking models get `thinkingLevel: "LOW"` when none is set. |
| `enableAffectiveDialog` | `boolean` | `false` | Affective dialog. |
| `proactivity` | `ProactivityConfig` | `{}` | Proactivity configuration. |
| `maxTokens` | `number \| null` | `4096` | Maximum output tokens. |
| `temperature`, `topK`, `topP`, `seed` | `number \| null` | `null` | Sampling settings. Gemini treats `seed` as best effort. |

### Notes

- Bot audio comes out as `TTSStartedFrame`, `TTSAudioRawFrame`s and `TTSStoppedFrame`, with the
  bot's transcript as `LLMTextFrame`s and `TTSTextFrame`s. User transcripts come out as
  `TranscriptionFrame`s, aggregated into sentences with a 0.5 second fallback timeout.
- With server-side VAD, the service emits no `UserStartedSpeakingFrame` or
  `UserStoppedSpeakingFrame`. Processors that depend on them (RTVI user speaking events, user
  idle and mute handling, turn recording) do nothing unless the user aggregator has a VAD
  analyzer. `LLMContextAggregatorPair` detects this service, so context writes are correct
  either way.
- Tools in the context take precedence over `tools` given at construction. Tools can't change
  mid-session: `LLMSetToolsFrame` is dropped, with a warning.
- Functions registered with `cancelOnInterruption: false` use Gemini's `NON_BLOCKING` tool
  behavior on models that support it (3.8 and later, and pre-3.0). On Gemini 3.x models before
  3.8, the service logs an error and pushes an error the first time one is used.
- Grounding metadata (for example from a Google Search tool) produces an
  `LLMSearchResponseFrame`, as with [`GoogleLLMService`](/docs/services/llm/google#notes).
- Video frames are throttled to one per second and sent as JPEG.
- The service reconnects after a connection error, resuming the session with the last
  resumption handle. After three consecutive failures it reports an error and stops.
- An `EndFrame` waits for the bot's turn to finish, for at most 30 seconds.
- On thinking models, a turn that Gemini reports as still in progress is held open, so a reply
  spanning several `turn_complete` messages is one assistant turn.
- A new system instruction or tools from the context make the service reconnect the session.

## Runtime notes

The client is `GoogleGenAI` from `@google/genai`, which opens the Live API over the global
`WebSocket`. Server messages arrive through the SDK's callbacks and are fed to the service's
receive task, so socket errors go through the same reconnect path as upstream.

`GeminiFileAPI` uses the global `fetch` (injectable with `fetch`). `uploadFile()` takes a path,
as upstream does, or the file's contents (a `Uint8Array`, an `ArrayBuffer`, a `Blob` or a
`ReadableStream`). Contents work on every runtime, Cloudflare Workers included. A path is read
with the injected `fs`, or with `node:fs/promises` imported on first use (Bun, Node, Deno); on a
runtime without it, a path throws an error that says to pass the contents. The MIME type comes
from `mimeType`, else the path's extension, else a `Blob`'s type, else `displayName`'s
extension, else `application/octet-stream`.

`historyConfig` is set on the connect config as upstream does, but `@google/genai` 2.27 does
not forward it in the setup message.

The deprecated upstream `InputParams` class and the `model`, `voiceId` and `params`
constructor options are not ported; use `settings`.
