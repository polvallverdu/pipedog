## Overview

- **`GroqSTTService`**: a `BaseWhisperSTTService` subclass. Each utterance (segmented by VAD) is sent to Groq's OpenAI-compatible transcription endpoint, and the text comes back as a `TranscriptionFrame`.

## Installation

```bash
bun add @pipedog/groq
```

```ts
import { GroqSTTService } from "@pipedog/groq/stt";
```

## Prerequisites

- A Groq account and an API key from the [Groq console](https://console.groq.com/).
- Pass the key as `apiKey`. It is required, and the service never falls back to
  `OPENAI_API_KEY`. The examples read it from `GROQ_API_KEY`.
- A VAD in the pipeline, since this is a segmented service: it transcribes each utterance
  once the user stops speaking.

## GroqSTTService

Base URL `https://api.groq.com/openai/v1`.

### Settings

Runtime-updatable settings, passed as `settings: new GroqSTTService.Settings({...})`
(`GroqSTTSettings`). Any setting you leave out keeps the default below.

| Setting | Type | Default | Description |
|---|---|---|---|
| `model` | `string` | `"whisper-large-v3-turbo"` | Whisper model. |
| `language` | `Language \| null` | `Language.EN` | Language of the audio. |
| `prompt` | `string \| null` | `null` | Text to guide the style, or to continue a previous segment. |
| `temperature` | `number \| null` | `null` | Sampling temperature, 0 to 1. |

### Notes

- Uploads each utterance as a WAV file, with `response_format: "json"` (`"verbose_json"` when `includeProbMetrics` is on, for per-segment probabilities).
- `httpClient` replaces the SDK's `fetch`, for example to set a longer request timeout.
- `pushEmptyTranscripts` pushes empty transcriptions instead of dropping them.

## Runtime notes

- The client is the `openai` JS SDK (through `@pipedog/whisper`) over `fetch`. It works on Bun, Node, Deno and Cloudflare Workers.
- The deprecated `model`, `language`, `prompt` and `temperature` constructor options are not ported. Use `settings`.
- Tested against fakes, not against Groq itself.
