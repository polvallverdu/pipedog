## Overview

pipedog ports both of Pipecat's Google speech-to-text services. They use different APIs and
different credentials:

- **`GeminiSTTService`**: streams audio to a Gemini Live transcription model
  (`gemini-3.5-transcribe-live` by default) over the Gemini Live API. Authenticates with a
  Gemini API key, or with Google Cloud credentials on Vertex AI. Supports automatic language
  detection, language hints, adaptation phrases and verbatim or smart transcription.
- **`GoogleSTTService`**: Google Cloud Speech-to-Text V2 streaming recognition. Authenticates
  with a Google Cloud service account or Application Default Credentials (ADC). Supports
  multiple languages, phrase-set adaptation, denoising and automatic stream renewal.

## Installation

```bash
bun add @pipedog/google
```

`GoogleSTTService` also needs the Cloud Speech Node SDK, an optional peer dependency:

```bash
bun add @google-cloud/speech
```

```ts
import { GeminiSTTService } from "@pipedog/google/gemini_live/stt";
import { GoogleSTTService } from "@pipedog/google/stt";
```

## Prerequisites

- **`GeminiSTTService`**: a Gemini API key from [Google AI Studio](https://aistudio.google.com/apikey),
  passed as `apiKey`. The examples read it from `GOOGLE_API_KEY`. On Vertex AI
  (`vertexai: true`), a Google Cloud project with the Vertex AI API enabled, and a service
  account key or ADC instead.
- **`GoogleSTTService`**: a Google Cloud project with the Speech-to-Text API enabled, and a
  service account key (as a file or a JSON string) or ADC. The examples read
  `GOOGLE_APPLICATION_CREDENTIALS` (a key file path) or `GOOGLE_CREDENTIALS_JSON` (the key
  itself). The project ID comes from the credentials.

### Vertex AI

`vertexai: true` (pipedog only) connects through Vertex AI instead of the Gemini Developer API.
It takes `location` (required, e.g. `"eu"` for data residency), `projectId` (defaults to
`GOOGLE_CLOUD_PROJECT`), and `credentials` (a service account JSON string) or `credentialsPath`,
falling back to Application Default Credentials, as the Vertex LLM services do. `apiKey` is
rejected in this mode.

<include cwd>snippets/services/stt-google-gemini.ts#vertex</include>

Vertex's Live API rejects the `languageAuto` and `languageHints` fields, so in this mode the
language codes are sent as `inputAudioTranscription.languageCodes`, and no codes means automatic
detection. `languageAuto: false` has no Vertex equivalent and is ignored.

### Reported language

Each transcription frame carries the language the model reports. That value can be wrong,
especially on short utterances. With `reportDetectedLanguage: false` (pipedog only), frames carry
the configured language when exactly one is configured, and `null` otherwise.

### Changing languages during a session

`setLanguageCodes(codes)` (pipedog only) sets the language codes to transcribe, for example when
the bot switches language. The codes are sent as-is and take precedence over the `language` and
`languages` settings until one of those is updated. An empty list means automatic detection. Pass
a function (`() => string[]`) to have the codes read each time they are needed.

<include cwd>snippets/services/stt-google-gemini.ts#switch-language</include>

The session does not reconnect at once. When the codes differ from the ones it was opened with,
the service reconnects on the next `BotStartedSpeakingFrame`. If the user is mid-turn then, it
waits until the turn ends, so no utterance is cut off. Audio that arrives while it reconnects is
buffered and sent to the new session. `GoogleSTTService` has the same method.

### Event handlers

| Event | Description |
|---|---|
| `on_connected` | Connected to the Gemini Live API. |
| `on_disconnected` | Disconnected from the Gemini Live API. |
| `on_connection_error` | The first connection failed, or three connection attempts failed in a row; the service stops retrying. |

### Notes

- Emits `InterimTranscriptionFrame`s as results arrive and a `TranscriptionFrame` for each
  finished utterance.
- On a `VADUserStoppedSpeakingFrame`, the service sends an audio-stream-end signal so the model
  finalizes the utterance at once. Without an upstream VAD, the model finalizes on its own
  schedule.
- Language hints and automatic detection are mutually exclusive. If both are set, hints win.
- Any settings change reconnects the session.
- The Live session is opened in the background when the `StartFrame` arrives, so the
  `StartFrame` (and the bot's first words) don't wait for it. Audio is buffered until the session
  is live. Upstream holds the `StartFrame` until the session is open; `awaitConnectionOnStart:
  true` (pipedog only) does the same.
- Audio is sent at the pipeline's input sample rate. The model works best with 16 kHz mono PCM.

## GoogleSTTService

### Configuration

<auto-type-table cwd path="../../packages/google/src/stt.ts" name="GoogleSTTServiceOptions" />

### Settings

Runtime-updatable settings, passed as `settings: new GoogleSTTService.Settings({...})`.

| Setting | Type | Default | Description |
|---|---|---|---|
| `model` | `string` | `"latest_long"` | Speech V2 model. |
| `languages` | `Language[]` | `[Language.EN_US]` | Recognition languages. |
| `languageCodes` | `string[] \| null` | `null` | Google language codes sent as-is, instead of `languages`, e.g. `["auto"]` for Chirp's language detection (pipedog only). |
| `language` | `Language \| null` | `null` | Setting it replaces `languages` (and `languageCodes`) with that one language. |
| `useSeparateRecognitionPerChannel` | `boolean` | `false` | Recognize each channel separately. |
| `enableAutomaticPunctuation` | `boolean` | `true` | Add punctuation. |
| `enableSpokenPunctuation` | `boolean` | `false` | Transcribe spoken punctuation. |
| `enableSpokenEmojis` | `boolean` | `false` | Transcribe spoken emojis. |
| `profanityFilter` | `boolean` | `false` | Filter profanity. |
| `enableWordTimeOffsets` | `boolean` | `false` | Word timings. |
| `enableWordConfidence` | `boolean` | `false` | Word confidence scores. |
| `enableInterimResults` | `boolean` | `true` | Emit interim results. |
| `enableVoiceActivityEvents` | `boolean` | `false` | Voice activity events. |
| `adaptation` | `SpeechAdaptation \| null` | `null` | Phrase sets that bias recognition. |
| `denoiserConfig` | `DenoiserConfig \| null` | `null` | Background-noise removal (Chirp 3 models only), e.g. `{ denoise_audio: true }`. |

`adaptation` and `denoiserConfig` are plain objects. Keys may be snake_case, as Google documents
them, or camelCase. A `phrase_sets` entry is a phrase set resource name or an inline phrase set.
Referenced phrase sets must live in the same location as the service.

|---|---|
| `on_connected` | The service connected. |
| `on_disconnected` | The service disconnected. |

### Notes

- Emits `InterimTranscriptionFrame`s (with `enableInterimResults`) and `TranscriptionFrame`s.
- Google limits a streaming call to a few minutes. The service renews the stream every 4
  minutes (`GoogleSTTService.STREAMING_LIMIT`, in ms) and carries the unfinished audio over.
- A settings change reconnects the stream.
- The `telephony` model rejects adaptation; the service logs a warning and transcribes without
  it.
- With inline `credentials`, a missing `project_id` throws in the constructor.
- With `languageCodes: ["auto"]`, transcripts carry the language Google detected.
- A gRPC CANCELLED error (the call was cancelled on our side) ends that stream quietly instead
  of being reported as an error.

### Finalizing on VAD stop

Google sends a final result only once its own endpointing decides the utterance is over, about
1.5 s after speech ends. With `finalizeOnVadStop: true` (pipedog only), the service half-closes
the request stream when a `VADUserStoppedSpeakingFrame` arrives, so Google returns the final for
the audio it has right away (about 0.6 s), and opens a new stream for the next audio, which waits
in the queue meanwhile. The finals of the closed stream are pushed as one finalized
`TranscriptionFrame`, so the turn can end without waiting for the STT timeout. Put a VAD before
the service.

```ts
const stt = new GoogleSTTService({
  location: "eu",
  finalizeOnVadStop: true,
  settings: new GoogleSTTService.Settings({ model: "chirp_3", languageCodes: ["auto"] }),
});
```

### Switching languages mid-call

`setLanguageCodes(codes)` (pipedog only, the same API as `GeminiSTTService`) changes the
`languageCodes` without cutting off the user: when the codes differ from the current ones, the
stream reconnects on the next `BotStartedSpeakingFrame`, or once the user's turn ends if they are
speaking over the bot. Pass a function to have the codes read again each time the bot starts
speaking; it stays in effect until the `language`, `languages` or `languageCodes` setting is
updated.

```ts
await stt.setLanguageCodes(["es-ES", "en-US"]);
// or follow the bot's language:
await stt.setLanguageCodes(() => [currentLanguageCode()]);
```

### Sharing a client and prewarming

With `sharedClient: true` (pipedog only), services with the same `location`, credentials,
`clientOptions` and `speechModule` use one Speech client per process instead of one each, so a
server running one pipeline per call opens one gRPC channel and fetches tokens once.
`prewarm()` connects it ahead of time (it loads the SDK, resolves the project ID, opens the
channel and fetches a token) and returns `false` with a warning instead of throwing if that
fails; the first stream then connects as usual.

```ts
const sttOptions = { location: "eu", sharedClient: true };
await new GoogleSTTService(sttOptions).prewarm(); // at server start-up
// per call:
const stt = new GoogleSTTService({ ...sttOptions, settings: new GoogleSTTService.Settings({ model: "chirp_3" }) });
```

It is off by default, as upstream builds a client per service, because a shared client puts
every concurrent stream of the process on one gRPC channel. Services never close their client,
so one call ending doesn't affect the others.

## Runtime notes

<RuntimeMatrix pkg="@pipedog/google" />

`GeminiSTTService` uses `GoogleGenAI` from `@google/genai`, which opens the Live API over the
global `WebSocket` and runs on Bun, Node, Deno and Cloudflare Workers. In Vertex AI mode it
authenticates through google-auth-library, which only the SDK's Node build supports, so that mode
runs on Bun, Node and Deno, not on Workers. The client is created on first connect, so a subclass
that overrides `_createClient()` can read its own fields there.

Cloud Speech-to-Text V2 streaming is gRPC only, so `GoogleSTTService` loads the Node SDK
`@google-cloud/speech` lazily on first connect. That needs a Node-compatible runtime, not
Workers. To use another transport, pass a `client` that implements `GoogleSTTClient`
(`streamingRecognize()` and, optionally, `getProjectId()`). `clientOptions` (pipedog only) is
merged into the SDK's `SpeechClient` options.

<Callout type="info">
Upstream resolves credentials and the project ID in the constructor. Here, with
`credentialsPath` or ADC, they are resolved on first connect (in `setup()`), so "No valid
credentials provided." and "Project ID not found in credentials" are raised there. Inline
`credentials` are still checked in the constructor.
</Callout>

The deprecated upstream `InputParams` class, the `params` option, `setLanguages()` and
`updateOptions()` are not ported. `GoogleSTTSettings.languageCodes`, deprecated upstream, is kept
for codes `Language` cannot express, such as `"auto"`.
