## Overview

- **`GradiumTTSService`**: streams text over a WebSocket to Gradium and pushes 48 kHz audio as it arrives.

## Installation

```bash
bun add @pipedog/gradium
```

```ts
import { GradiumTTSService } from "@pipedog/gradium/tts";
```

## Prerequisites

- A Gradium account and an API key from [Gradium](https://gradium.ai/).
- Pass the key as `apiKey`. The examples read it from `GRADIUM_API_KEY`.

## GradiumTTSService

Connects to `wss://api.gradium.ai/api/speech/tts`, with the key in the `x-api-key` header.

### Settings

Runtime-updatable settings, passed as `settings: new GradiumTTSService.Settings({...})`
(`GradiumTTSSettings`). Any setting you leave out keeps the default below.

| Setting | Type | Default | Description |
|---|---|---|---|
| `model` | `string` | `"default"` | Speech model. |
| `voice` | `string` | `"_6Aslh2DxfmnRLmP"` | Voice id. Changing it reconnects the socket. |
| `language` | `Language \| null` | `null` | Language. |

### Notes

- The sample rate is fixed at 48000 Hz.
- `jsonConfig` takes a JSON string of extra model settings, sent with the setup message.

## Runtime notes

- The WebSocket goes through the core `websocketConnect`, with headers on the handshake.
- The deprecated `InputParams`, `params`, `voice_id` and `model` constructor options are not ported.
- Tested against a local WebSocket server (upstream has no Gradium TTS test), not against Gradium itself.
