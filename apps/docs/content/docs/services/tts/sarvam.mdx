## Overview

- **`SarvamTTSService`**: streams text over Sarvam's WebSocket and pushes audio as it arrives. Interruptions reconnect the socket.
- **`SarvamHttpTTSService`**: one HTTP request per sentence.

## Installation

```bash
bun add @pipedog/sarvam
```

```ts
import { SarvamHttpTTSService, SarvamTTSService } from "@pipedog/sarvam/tts";
```

## Prerequisites

- A Sarvam account and an API key from the [Sarvam dashboard](https://dashboard.sarvam.ai/).
- Pass the key as `apiKey`. The examples read it from `SARVAM_API_KEY`.

## Models

| Model | Pitch and loudness | Temperature | Pace | Sample rate |
|---|---|---|---|---|
| `bulbul:v3` (default), `bulbul:v3-beta` | ignored | 0.01 to 1.0 | 0.5 to 2.0 | 24000 Hz by default |
| `bulbul:v4-flash` | supported | ignored | 0.5 to 2.0 | 24000 Hz by default |

`TTS_MODEL_CONFIGS` holds each model's speakers and limits, and `getSpeakersForModel(model)` lists
its speakers. Preprocessing is always on for these models. Settings a model doesn't support are
dropped or clamped when the service is constructed.

### Settings

Runtime-updatable settings, passed as `settings: new SarvamTTSService.Settings({...})`
(`SarvamTTSSettings`). Any setting you leave out keeps the default below.

| Setting | Type | Default | Description |
|---|---|---|---|
| `model` | `string` | `"bulbul:v3"` | TTS model. |
| `voice` | `string` | `"shubh"` | Speaker. |
| `language` | `Language` | `"en-IN"` | Language of the text. |
| `enablePreprocessing` | `boolean \| null` | `false` | Text preprocessing. Always on for v3 and v4-flash. |
| `pace` | `number \| null` | `1.0` | Speech pace, 0.5 to 2.0. |
| `pitch` | `number \| null` | `null` | Pitch (`bulbul:v4-flash`). |
| `loudness` | `number \| null` | `null` | Volume multiplier (`bulbul:v4-flash`). |
| `temperature` | `number \| null` | `null` | Randomness, 0.01 to 1.0 (`bulbul:v3`; the server's default is 0.6). |
| `minBufferSize` | `number \| null` | `50` | Characters to buffer before generating audio. |
| `maxChunkLength` | `number \| null` | `150` | Largest chunk, in characters, processed at once. |

### Notes

- The socket carries `config`, `text`, `flush` and `ping` messages. The API key and a `User-Agent` go in the handshake headers.
- `sampleRate` can be 8000, 16000, 22050 or 24000; `null` uses the model's default.

### Notes

- `fetch` replaces the global `fetch` (upstream takes an aiohttp session).
- `baseUrl` defaults to `https://api.sarvam.ai`. The WAV header of each reply is stripped before the audio is pushed.
- `sampleRate` can also be 32000, 44100 or 48000 for `bulbul:v3`.

## Runtime notes

- HTTP goes through `fetch` and the WebSocket through the core `websocketConnect`. Both work on Bun, Node, Deno and Cloudflare Workers.
- `bulbul:v2`, the `InputParams` class and the `model`, `voice_id`, `params` and `aggregate_sentences` constructor options are deprecated upstream and not ported.
- Tested against local servers, not against Sarvam itself.
