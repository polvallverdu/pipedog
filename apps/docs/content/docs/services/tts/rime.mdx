## Overview

Rime's Coda and Mist models turn text into speech. pipedog ports these Pipecat services:

- **`RimeTTSService`**: Rime's JSON WebSocket API (`/ws3`), with word timestamps and one audio
  context per turn.
- **`RimeHttpTTSService`**: Rime's HTTP API, streaming raw PCM, for when a WebSocket is not
  needed.
- **`RimeV1TTSService`**: Rime's WebSocket v1 API, which carries protobuf envelopes (binary or
  proto3 JSON). Interruptions cancel a context without reconnecting, and Rime can accumulate
  streamed LLM tokens into sentences.

## Installation

```bash
bun add @pipedog/rime
```

```ts
import { RimeHttpTTSService, RimeTTSService } from "@pipedog/rime/tts";
import { RimeV1TTSService } from "@pipedog/rime/tts_v1";
```

## Prerequisites

- A Rime account and an API key from the [Rime dashboard](https://rime.ai).
- A voice (`speaker`) for the model you use. There is no default voice.
- Pass the key as `apiKey`. The examples read it from `RIME_API_KEY`.

### Settings

Runtime-updatable settings, passed as `settings: new RimeTTSService.Settings({...})`.
`RimeHttpTTSService` uses the same settings class. Each setting is only sent when set; the
sampling settings go to `coda` and the `mistv2` ones to the other models.

| Setting | Type | Default | Description |
|---|---|---|---|
| `model` | `string` | `"coda"` | Rime model: `coda`, or a Mist model such as `mistv2`. |
| `voice` | `string \| null` | `null` | Voice (`speaker`). Set one. |
| `language` | `Language \| null` | `null` | Language. Sent as a Rime code such as `eng`. |
| `segment` | `string \| null` | `null` | `"immediate"`, `"bySentence"` or `"never"`. |
| `speedAlpha` | `number \| null` | `null` | Speech speed multiplier. |
| `inlineSpeedAlpha` | `string \| null` | `null` | Inline speed markup. |
| `repetitionPenalty`, `temperature`, `topP` | `number \| null` | `null` | Coda sampling (wire names `repetition_penalty`, `temperature`, `top_p`). |
| `timeScaleFactor` | `number \| null` | `null` | Coda playback speed. Above 1.0 slows the audio down. |
| `reduceLatency`, `pauseBetweenBrackets`, `phonemizeBetweenBrackets`, `noTextNormalization`, `saveOovs` | `boolean \| null` | `null` | Mist options. |

### Event handlers

Inherited from `TTSService`:

| Event | Description |
|---|---|
| `on_connected` | Connected to Rime. |
| `on_disconnected` | Disconnected from Rime. |
| `on_connection_error` | The connection failed. |
| `on_tts_request` | A text chunk is about to be sent for synthesis. |

### Notes

- Every setting is a query parameter of the WebSocket URL, so any change reconnects.
- The service does not push the LLM's text frames. It builds `TTSTextFrame`s from Rime's word
  timestamps.
- Text inside `spell(...)` is never split across aggregates.
- `PRONOUNCE()` and `INLINE_SPEED()` add fields to the next message only.

## RimeV1TTSService

### Configuration

<auto-type-table cwd path="../../packages/rime/src/tts_v1.ts" name="RimeV1TTSServiceOptions" />

### Settings

Passed as `settings: new RimeV1TTSService.Settings({...})`. `model` is required at construction.
Each context uses the settings in effect when it starts. A setting the model does not accept is
left out with a warning.

| Setting | Type | Description |
|---|---|---|
| `model` | `string` | Required. `"coda"` and `"mistv3"` select their public endpoints. Changing it later is reported, not applied. |
| `voice` | `string \| null` | Voice (`speaker`). |
| `language` | `Language \| null` | Sent as a BCP-47 tag such as `en`. |
| `timeScaleFactor` | `number \| null` | Playback speed. Not for mistv2. |
| `textLookaheadTokens` | `number \| null` | Tokens to collect before audio starts (Coda only). |
| `pauseBetweenBrackets`, `phonemizeBetweenBrackets`, `saveOovs` | `boolean \| null` | Mist options. |

### Usage

<include cwd meta='title="v1.ts"'>snippets/services/tts-rime.ts#v1</include>

### Notes

- Pass `websocketUrl` for a custom deployment. The model is never inferred from the URL.
- Rime v1 sends a `ready` event before the first context. The service waits up to 10 seconds
  for it and reports a connection error otherwise.
- A failed context is reported with the error's `ErrorCategory`, and the service stays usable for
  the next turn.
- Rime v1 does not report word timestamps.

## Runtime notes

- The WebSocket services use the global `WebSocket` and send the key as an `Authorization`
  header on the handshake. That works on Bun, Node and Deno, and on Cloudflare Workers, where the
  socket is opened through `fetch`.
- `RimeV1TTSService` reads the negotiated subprotocol (`rime.v1.binary` or `rime.v1.json`) from
  the socket and refuses a connection that did not accept it.
- The protobuf messages come from Rime's own package, `@rimelabs/api`, with `@bufbuild/protobuf`.
  Both are plain JavaScript.
- `RimeHttpTTSService` uses `fetch`. Upstream's required `aiohttp_session` is replaced by an
  optional `fetch` option.
- Not ported: the deprecated `RimeNonJsonTTSService` and the `InputParams` classes, and the
  `voiceId`, `model`, `params` and `aggregateSentences` constructor options.
- Whole-number floats, such as `PAUSE_TAG(0.5)`'s `500`, print without Python's `.0`.
