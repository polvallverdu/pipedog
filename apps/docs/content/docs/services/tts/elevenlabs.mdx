## Overview

ElevenLabs turns text into speech with its Flash, Turbo, Multilingual and v3 models. pipedog
ports all three of Pipecat's ElevenLabs text-to-speech services:

- **`ElevenLabsTTSService`**: streams over ElevenLabs' multi-context WebSocket API
  (`multi-stream-input`), with word-level timestamps and per-turn audio contexts.
- **`ElevenLabsHttpTTSService`**: posts each request to the `stream/with-timestamps` HTTP
  endpoint and streams the audio and alignment back.
- **`ElevenLabsDialogueTTSService`**: streams over ElevenLabs' multi-context Text to Dialogue
  WebSocket, which serves the Eleven v3 and v4 dialogue models.

## Installation

```bash
bun add @pipedog/elevenlabs
```

```ts
import { ElevenLabsDialogueTTSService } from "@pipedog/elevenlabs/dialogue/tts";
import { ElevenLabsHttpTTSService, ElevenLabsTTSService } from "@pipedog/elevenlabs/tts";
```

## Prerequisites

- An ElevenLabs account and an API key from the
  [ElevenLabs dashboard](https://elevenlabs.io/app/settings/api-keys).
- A voice id from the ElevenLabs voice library. There is no default voice.
- Pass the key as `apiKey`. The examples read it from `ELEVENLABS_API_KEY`.

## ElevenLabsTTSService

### Configuration

### Settings

Runtime-updatable settings, passed as `settings: new ElevenLabsTTSService.Settings({...})`. Any
setting you leave out keeps the default below. `null` means the field is not sent, so ElevenLabs
uses its own default.

| Setting | Type | Default | Description |
|---|---|---|---|
| `model` | `string` | `"eleven_flash_v2_5"` | ElevenLabs model id. |
| `voice` | `string \| null` | `null` | Voice id. Set one: there is no default. |
| `language` | `Language \| null` | `null` | Synthesis language. Sent only to models that take a language code. |
| `stability` | `number \| null` | `null` | Voice stability, 0.0 to 1.0. |
| `similarityBoost` | `number \| null` | `null` | Similarity boost, 0.0 to 1.0. |
| `style` | `number \| null` | `null` | Style exaggeration, 0.0 to 1.0. |
| `useSpeakerBoost` | `boolean \| null` | `null` | Speaker boost. |
| `speed` | `number \| null` | `null` | Speaking speed, 0.7 to 1.2. |
| `applyTextNormalization` | `"auto" \| "on" \| "off" \| null` | `null` | Text normalization mode. |

### Event handlers

Inherited from `TTSService`:

| Event | Description |
|---|---|
| `on_connected` | Connected to ElevenLabs. |
| `on_disconnected` | Disconnected from ElevenLabs. |
| `on_connection_error` | The connection failed. |
| `on_tts_request` | A text chunk is about to be sent for synthesis. |

### Notes

- The service does not push the LLM's text frames itself. It builds `TTSTextFrame`s from
  ElevenLabs' word alignment, so the context only records words the user actually heard.
- Text is aggregated into sentences by default. `autoMode` left `null` is `true` in sentence
  mode and `false` in token mode, where ElevenLabs' chunk scheduler needs to gather enough text.
- Changing `voice`, `model` or `language` reconnects, since they are part of the WebSocket URL.
  Changing `stability`, `similarityBoost`, `style`, `useSpeakerBoost` or `speed` closes the
  current audio context, so the next one opens with the new voice settings.
- `language` is checked against the model's language list. A model that takes no language code,
  or doesn't cover the language, gets none, and this is logged.
- The output format is chosen from the sample rate: 8000, 16000, 22050, 24000, 32000, 44100 or
  48000 Hz. Any other rate falls back to `pcm_24000` with a warning.
- `pronunciationTransformIpa()` renders IPA as SSML `<phoneme>` tags. Only `eleven_flash_v2`
  and `eleven_turbo_v2` read them, and this service also needs `enableSsmlParsing: true`.
  Otherwise the transform is skipped.
- Other settings changes (such as `applyTextNormalization`) are not applied mid-call and are
  logged as unhandled, unless a URL change reconnects at the same time.

### Usage

<include cwd meta='title="http.ts"'>snippets/services/tts-elevenlabs.ts#http</include>

### Notes

- Word timestamps come from the `with-timestamps` endpoint, so this service also emits
  `TTSTextFrame`s aligned with playback.
- Earlier text in the turn is sent as `previous_text`, for continuity between requests.
- `enableLogging: false` turns on ElevenLabs' zero retention mode (enterprise only).
- IPA pronunciations (`pronunciationTransformIpa()`) work with `eleven_flash_v2` and
  `eleven_turbo_v2` only.

## ElevenLabsDialogueTTSService

### Configuration

<auto-type-table cwd path="../../packages/elevenlabs/src/dialogue/tts.ts" name="ElevenLabsDialogueTTSServiceOptions" />

### Settings

Runtime-updatable settings, passed as `settings: new ElevenLabsDialogueTTSService.Settings({...})`.

| Setting | Type | Default | Description |
|---|---|---|---|
| `model` | `string` | `"eleven_v4_turbo"` | An `eleven_v3` or `eleven_v4` model. Any other model logs a warning. |
| `voice` | `string \| null` | `null` | Voice id. Registered per context, so a change only opens a new context. |
| `language` | `Language \| null` | `null` | Synthesis language, sent as `language_code` where the model supports it. |
| `stability` | `number \| null` | `null` | Voice stability, 0.0 to 1.0. The only voice setting Text to Dialogue reads. |

A `model` or `language` change reconnects the WebSocket. A `voice` or `stability` change closes the
current audio context, and the next one registers the new values.

### Usage

<include cwd meta='title="dialogue.ts"'>snippets/services/tts-elevenlabs.ts#dialogue</include>

### Notes

- Text is always aggregated by sentence, and a trailing space is added to each input, because the
  server joins inputs verbatim. A `textAggregationMode` other than `SENTENCE` is ignored with a
  warning.
- Eleven v3 and v4 perform inline audio tags such as `[laughs]`. They come back as spoken
  characters in the alignment, so they reach the LLM context unless a text filter removes them.
- A keepalive context is registered when the socket opens, because the server drops a connection
  that is idle for 20 seconds and rejects a keepalive that names no registered context. Set a
  `voice` so it can be registered.
- `pronunciationTransformIpa()` renders pronunciations as IPA between slashes, which Eleven v3
  reads.
- `seed` makes generation reproducible.

## Runtime notes

- `ElevenLabsTTSService` uses the global `WebSocket` and sends the key as an `xi-api-key` header
  on the handshake. That works on Bun, Node and Deno, and on Cloudflare Workers, where the socket
  is opened through `fetch`. Upstream sets a 16 MB message size limit; the standard `WebSocket`
  has none.
- `ElevenLabsDialogueTTSService` uses the same WebSocket and `xi-api-key` header as
  `ElevenLabsTTSService`, so it runs wherever that does.
- `ElevenLabsHttpTTSService` uses `fetch`. Upstream's required `aiohttp_session` is replaced by
  an optional `fetch` option (the global `fetch` by default).
- Not ported: the deprecated `PronunciationDictionaryLocator`, the `InputParams` classes and the
  `voiceId`, `model`, `params`, `pronunciationDictionaryLocators` and `aggregateSentences`
  constructor options. Use `settings` and `textAggregationMode`.
