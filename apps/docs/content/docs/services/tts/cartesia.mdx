## Overview

Cartesia's Sonic models turn text into speech. pipedog ports both of Pipecat's Cartesia
text-to-speech services:

- **`CartesiaTTSService`**: streams over Cartesia's WebSocket API. Audio arrives as it is
  generated, with word-level timestamps that keep the spoken text in step with playback.
- **`CartesiaHttpTTSService`**: posts each request to Cartesia's `/tts/bytes` HTTP endpoint and
  gets the audio back in one piece, without word timestamps.
- **`GenerationConfig`**: volume, speed and emotion for sonic-3 series models, shared by both.

## Installation

```bash
bun add @pipedog/cartesia
```

```ts
import {
  CartesiaEmotion,
  CartesiaHttpTTSService,
  CartesiaTTSService,
  GenerationConfig,
} from "@pipedog/cartesia/tts";
```

## Prerequisites

- A Cartesia account and an API key from the [Cartesia playground](https://play.cartesia.ai).
- A voice id from the Cartesia voice library. There is no default voice.
- Pass the key as `apiKey`. The examples read it from `CARTESIA_API_KEY`.

### Settings

Runtime-updatable settings, passed as `settings: new CartesiaTTSService.Settings({...})`. Both
services use the same settings class.

| Setting | Type | Default | Description |
|---|---|---|---|
| `model` | `string` | `"sonic-3.6"` | Cartesia TTS model. |
| `voice` | `string \| null` | `null` | Voice id. Set one: there is no default. |
| `language` | `Language` | `Language.EN` | Synthesis language. |
| `generationConfig` | `GenerationConfig \| null` | `null` | Volume, speed and emotion. See below. |
| `pronunciationDictId` | `string \| null` | `null` | Cartesia pronunciation dictionary id. |

### Event handlers

Inherited from `TTSService`:

| Event | Description |
|---|---|
| `on_connected` | Connected to Cartesia. |
| `on_disconnected` | Disconnected from Cartesia. |
| `on_connection_error` | The connection failed. |
| `on_tts_request` | A text chunk is about to be sent for synthesis. |

### Notes

- The service does not push the LLM's text frames itself. It builds `TTSTextFrame`s from
  Cartesia's word timestamps, so the context only records words the user actually heard.
- Text is aggregated into sentences by default. `TextAggregationMode.TOKEN` streams tokens
  directly for lower latency.
- `maxBufferDelayMs` sets Cartesia's server-side buffer. Left `null`, it is `0` in sentence mode
  (no double buffering) and unset in token mode (Cartesia's 3000 ms default).
- A `voice`, `model` or `language` change takes effect from the next sentence, which opens a new
  Cartesia context.
- Static helpers build Cartesia SSML tags for text transforms: `SPELL`, `EMOTION_TAG`,
  `PAUSE_TAG`, `VOLUME_TAG` and `SPEED_TAG`. Text inside `<spell>` tags is never split across
  aggregates.
- `pronunciationTransformIpa()` turns IPA into Cartesia inline phonemes. Register it last in
  `textTransforms` so later transforms don't rewrite its markup.

## Runtime notes

<RuntimeMatrix pkg="@pipedog/cartesia" />

- `CartesiaTTSService` uses the global `WebSocket` and sends the key as an `X-API-Key` header on
  the handshake. The Bun, Node and Deno `WebSocket` support handshake headers, and on Cloudflare
  Workers the socket is opened through `fetch`.
- `CartesiaHttpTTSService` uses the global `fetch` unless you pass `fetch`. That option replaces
  upstream's `aiohttp_session`.
- The Cartesia API version header is pinned to `2026-03-01`. Upstream's `cartesia_version`
  option is not ported.
- Not ported: the deprecated `voiceId`, `model`, `params` (`InputParams`) and
  `aggregateSentences` constructor options. Use `settings` and `textAggregationMode`.
