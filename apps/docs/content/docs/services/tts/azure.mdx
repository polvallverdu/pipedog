## Overview

pipedog ports both of Pipecat's Azure text-to-speech services:

- **`AzureTTSService`**: streams each sentence's audio over the Speech service's WebSocket
  synthesis protocol, with word boundaries turned into word-timed `TTSTextFrame`s.
- **`AzureHttpTTSService`**: one `POST` to the REST endpoint per sentence, returning the whole
  sentence's audio.

Both build the same SSML from their settings (voice, style, prosody, emphasis, HD voice parameters,
locale pinning). Upstream drives Azure through the native Speech SDK; pipedog speaks the service's
WebSocket and REST protocols directly, so no SDK is needed.

## Installation

```bash
bun add @pipedog/azure
```

```ts
import { AzureHttpTTSService, AzureTTSService } from "@pipedog/azure/tts";
```

## Prerequisites

- An Azure AI Speech (or Azure AI Foundry) resource, with its key and region from the portal's
  **Keys and Endpoint** page.
- Pass the key as `apiKey` and the region (e.g. `"eastus"`) as `region`, or a Private Link or
  custom-domain URL as `privateEndpoint`. The examples read them from `AZURE_SPEECH_API_KEY` and
  `AZURE_SPEECH_REGION`.

### Settings

Runtime-updatable settings, passed as `settings: new AzureTTSService.Settings({...})`. Any
setting you leave out keeps the default below. `AzureHttpTTSService` uses the same settings class.

| Setting | Type | Default | Description |
|---|---|---|---|
| `voice` | `string` | `"en-US-SaraNeural"` | Azure voice name. |
| `language` | `Language \| string` | `"en-US"` | `xml:lang` of the SSML. |
| `forceLocale` | `boolean` | `false` | Wrap the text in `<lang xml:lang>` so a multilingual voice speaks in `language` instead of auto-detecting. |
| `style` | `string \| null` | `null` | Speaking style (`"cheerful"`, `"sad"`, ...), as `<mstts:express-as>`. |
| `styleDegree` | `string \| null` | `null` | Style intensity, 0.01 to 2.0. |
| `role` | `string \| null` | `null` | Role-play voice (`"YoungAdultFemale"`, ...). |
| `rate` | `string \| null` | `null` | Prosody rate (`"1.25"`, `"slow"`). |
| `pitch` | `string \| null` | `null` | Prosody pitch (`"+10%"`, `"-5Hz"`). |
| `volume` | `string \| null` | `null` | Prosody volume (`"+20%"`, `"loud"`). |
| `emphasis` | `string \| null` | `null` | `"strong"`, `"moderate"` or `"reduced"`. |
| `effect` | `string \| null` | `null` | Device effect: `"eq_car"`, or `"eq_telecomhp8k"` with an 8 kHz pipeline. |
| `voiceParameters` | `string \| null` | `null` | HD voice parameters (`"temperature=0.7;top_p=0.8"`). |

### Notes

- The synthesis connection opens on the first sentence and is reused. Audio is raw 16-bit mono PCM
  at the pipeline's output rate (8, 16, 22.05, 24, 44.1 or 48 kHz; other rates fall back to
  24 kHz).
- Word boundaries become `TTSTextFrame`s timed against the audio. Trailing punctuation is merged
  into the word before it, and Chinese, Japanese and Korean characters are merged up to the next
  punctuation or space. The last word always arrives before the `TTSStoppedFrame`.
- On an interruption the connection is closed, which stops Azure from sending more audio for the
  interrupted sentence; the next sentence opens a new one. Upstream calls the SDK's
  `stop_speaking_async()` instead.

### Notes

- Posts the SSML to `https://<region>.tts.speech.microsoft.com/cognitiveservices/v1` (or
  `<privateEndpoint>/tts/cognitiveservices/v1`) and yields the sentence as one audio frame.
- It requests a `raw-*-16bit-mono-pcm` format, which has no WAV header. Upstream strips the 44
  header bytes of the SDK's RIFF result instead.
- Pass `fetch` to send the request through your own client.

## Runtime notes

Both services work on Bun, Node, Deno and Cloudflare Workers: `AzureTTSService` uses core's
`websocketConnect`, `AzureHttpTTSService` uses `fetch`. The key is sent as the
`Ocp-Apim-Subscription-Key` header, and `AzureTTSService` also sends it as a query parameter, as
the Speech SDK does, for runtimes whose `WebSocket` can't send headers. With a custom-domain
`privateEndpoint`, `AzureTTSService` first asks the endpoint for its regional redirect, as the SDK
does.

The deprecated `voice`, `params` (`InputParams`) and `aggregateSentences` options aren't ported;
use `settings` and `textAggregationMode`.
