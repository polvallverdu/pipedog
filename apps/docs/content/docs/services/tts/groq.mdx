## Overview

- **`GroqTTSService`**: posts each sentence to Groq's `/audio/speech` endpoint and pushes the WAV it returns as audio frames.

## Installation

```bash
bun add @pipedog/groq
```

```ts
import { GroqTTSService } from "@pipedog/groq/tts";
```

## Prerequisites

- A Groq account and an API key from the [Groq console](https://console.groq.com/).
- Pass the key as `apiKey`. The examples read it from `GROQ_API_KEY`.

## GroqTTSService

Posts to `https://api.groq.com/openai/v1/audio/speech`.

### Settings

Runtime-updatable settings, passed as `settings: new GroqTTSService.Settings({...})`
(`GroqTTSSettings`). Any setting you leave out keeps the default below.

| Setting | Type | Default | Description |
|---|---|---|---|
| `model` | `string` | `"canopylabs/orpheus-v1-english"` | Speech model. |
| `voice` | `string` | `"autumn"` | Voice. |
| `language` | `string` | `"en"` | Language. |
| `speed` | `number \| null` | `1.0` | Speed. Groq only supports 1.0 for now. |

### Notes

- `outputFormat` is `"wav"` by default; the frames carry the WAV's own sample rate and channel count.
- A failed request produces an `ErrorFrame` instead of audio.

## Runtime notes

<RuntimeMatrix pkg="@pipedog/groq" />

- Requests go through `fetch` (upstream uses the `groq` SDK). It works on Bun, Node, Deno and Cloudflare Workers.
- The whole response is read and parsed as one WAV. Upstream parses each streamed chunk as a WAV.
- The deprecated `InputParams` and the `params`, `model_name` and `voice_id` options are not ported. Use `settings`.
- Tested against a local fake, not against Groq itself.
